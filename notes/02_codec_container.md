# 自前符号器のコンテナ（PCC2）— 設計メモ

## なぜ器から始めるのか

これまでの構成は「LASzip の前段に入る正規化レイヤー」だった。
この形には次の限界がある。

1. **幾何 22.2 bpp（全体の 41%）は丸ごと LASzip のもの**で、我々の寄与がゼロ。
2. 器が LAS の点形式に縛られるため、KITTI・TLS・PLY を同じ土俵に載せられない。
3. 「取得表現への復帰」で得た表現（極座標格子など）を、そのまま格納する場所がない。
   いまは LAS の X/Y/Z に押し込むか、外部ストリームに逃がすしかない。

符号器そのものを開発するなら、まず**自分の器**が要る。

## 設計原則（既存の成果から継承するもの）

| 原則 | 根拠 |
|---|---|
| **恒等候補を必ず持ち、実測で選ぶ** | 命題1（悪化しない保証）。判定誤りは +13% / −174% の非対称 |
| **副情報を必ず勘定に入れる** | 小さいファイルで見かけの利得が出るのを防ぐ |
| **順序は表現の一部** | 取得順 22.219 / Morton 28.232 bpp。並べ替えは破壊的操作 |
| **精度は申告制** | exact か bounded か。bounded の上限は推定でなく全点実測値 |
| **決定論的** | 整数のみ。浮動小数の丸めは処理系で変わる |
| **自己記述的** | 復号に元ファイルを要求しない（PCC1 は点数を外から渡していた） |

## 形式

すべてリトルエンディアン。文字列は `u16 長さ + バイト列`。

```
  0  magic     'PCC2'
  4  u16       version = 1
  6  u16       flags
  8  u64       n（点数）
 16  u32       header_len
 20  header    タグ付きレコードの列（下記）
     u32       n_streams
     directory ストリーム記述 × n_streams
     data      ストリーム本体を連結
     u64       crc64（ここまで全バイト。決定性の確認用）
```

### header のタグ

| tag | 内容 |
|---|---|
| 1 | 出所の種別（las / kitti / ply / …） |
| 2 | 元ファイルのバイト数 |
| 3 | scale[3]（f64） |
| 4 | offset[3]（f64） |
| 5 | スキーマ: 列数、各列の（名前, 型, 役割, ExtraBytes か） |
| 6 | 正規化の計画（既存 `Plan::to_json`。副情報としてここに入り、必ず勘定される） |
| 7 | 精度の申告: mode(exact/bounded), 宣言した誤差上限, 実測した最大誤差 |
| 8 | 封筒（元の器を再生成するのに要る情報。LAS ヘッダなど） |
| 9 | 幾何として扱う 3 列の名前 |

### ストリーム記述

```
u16 列数, 列名 × 列数, u16 符号器 id, u32 パラメタ長, パラメタ, u64 データ長
```

1 つのストリームが複数の列を担当してよい（幾何 3 軸を同時に符号化するため）。

### 符号器 id

| id | 名前 | 内容 |
|---|---|---|
| 0 | RAW64 | int64 をそのまま。**恒等候補**。これがあるので器は必ず有限長で閉じる |
| 1 | RANGE | zigzag + 適応二値レンジ符号（文脈なし） |
| 2 | RANGE_DELTA | 1 次差分 → zigzag + レンジ符号 |
| 3 | RANGE_CTX | 1 次差分 → zigzag、**直前の値のビット数を文脈にする** |
| 10 | GEOM_XYZ | 幾何 3 軸を同時に。軸ごと 1 次差分＋ビット数文脈 |
| 20 | ATTR_SPATIAL | 幾何由来の順序で先行する近傍 P 個から予測（既存 attr.cpp） |

採否は**全候補を実際に符号化して短いものを採る**。推定は使わない
（`lossless_refinements.md` の 3.1 bit/点はこの置き換えだけで戻った）。

## 幾何符号器の初期方針

超えるべき線は **LASzip の 22.219 bpp（AHN4 200万点・取得順）**。
既測の素朴な予測器は届いていない（1 次差分 25.292 / 2 次 25.875 / 3 次 28.876）。

差は予測式ではなく**文脈分割**にある。LASzip は整数を符号化するとき、
直前に符号化した値の大きさごとに別の確率モデルを使う。
`RANGE_CTX` はこれを最小構成で写したもので、まずここを測る。

## 検証

`pack` → `unpack` → 全列の完全一致を毎回確認する。通らなければ数字を出さない。
評価は常に 5 軸（bpp / enc 時間 / dec 時間 / ピークメモリ / 決定性）。
決定性は crc64 を 2 回の符号化で照合して示す。
