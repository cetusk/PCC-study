# 組み合わせを実装した結果 — 前提のほうが誤っていた

## やろうとしたこと

`end_to_end_comparison.md` で「幾何は G-PCC が 10.2% 良く、属性は本手法が 41.8% 良い。
組み合わせれば LASzip 比 −12.6% になるはず」と見積もった。これを実装して確かめた。

## 実装

幾何を外部符号器に任せる場合、**点の順序が問題になる**。
G-PCC は出力順を保存しないので、復号器は座標から正準順序を作れなければならない。
両側で Morton 順を独立に計算し、属性はその順で符号化する。
座標が完全に同じ点どうしの並びは幾何から決まらないが、
どちらにどの属性が付くかは幾何由来の情報ではないので、
検証は (座標, 属性) の多重集合の一致で行う。

`pccnorm combine <元LAZ> <復号済み幾何PLY> <幾何ストリーム>` として実装した。

## 結果 1 — 色だけなら見積もりどおり

```
幾何ストリーム（G-PCC）      25.363 bpp

> **設定についての注記（`scan_model_fitting.md` 25 節）。** ここで使っている
> G-PCC の幾何 25.363 bpp は**無調整に近い設定**の値である。設定を 8 通り
> 振ると同じデータの同じ点数で 24.375（IDCM=2）まで下がる。
> 新しい比較では調整済みの値を使っているので、25.363 とは直接比べられない。

属性容器（幾何を 0 にした LAZ） 0.092
属性の残差 + 仕様              7.434
合計                          32.889 bpp     検証: 属性 完全一致=true
```
見積もり 32.80 に対し実測 32.889。差は容器の固定費である。**加算は成り立った。**

## 結果 2 — 全フィールドでは壊れる

同じ構成に元データの 18 フィールドすべてを通すと **72.410 bpp**。
LASzip 経路の 54.082 bpp より遥かに悪い。

原因は Morton 整列である。取得順に依存する属性が壊れる。

| フィールド | 格納順 | Morton 順 | 変化 |
|---|---|---|---|
| gps_time | 2.263 b | 14.546 b | **−543%** |
| point_source_id | 0.001 b | 0.271 b | −24796% |
| user_data | 0.001 b | 0.771 b | −68522% |
| scan_angle | 0.191 b | 0.742 b | −288% |

G-PCC は全点を単一の幾何由来順序に並べ替えることを強制する。
本手法の容器は取得順を保ったまま、空間予測の残差ストリームだけを Morton 順にする。
**前者は取得順の構造を捨てるが、後者は両方使える。**

## 結果 3 — 見積もりの前提そのものが誤っていた

より重大な問題が見つかった。「G-PCC の幾何が LASzip より 10.2% 良い」は、
**私が入力を Morton 整列させたことによる見かけ**だった。

```
LASzip の幾何のみ（AHN4 200万点）
  格納順（取得順のまま）   22.219 bpp
  Morton 順に整列           28.232 bpp      ← 整列で +27.1% 悪化
  G-PCC（順序に依存しない）  25.363 bpp
```

**取得順のままなら LASzip の幾何のほうが G-PCC より 12.4% 良い。**
LASzip の幾何予測器は走査線に沿った逐次予測であり、取得順が最も得意な入力である。
Morton 整列はそれを壊す。

整列した理由は「順序の保存にはビットがかかるので、そのままでは LASzip が不利になる」
というものだったが、これは誤りである。LASzip は順序を保存するために余計に払っては
いない。渡された列を符号化しているだけで、取得順がたまたま最も安い列だった。
逆に G-PCC は順序を復元できないのだから、順序が必要なら G-PCC のほうが不足している。

## 訂正後の比較

AHN4、幾何と色 3 成分、すべて可逆・全点照合済み。単位 bit/点。

| 方式 | 順序 | 200万点 幾何 / 色 / 計 | 800万点 計 |
|---|---|---|---|
| G-PCC 階層予測 | 幾何由来 | 25.363 / 12.780 / **38.143** | **38.574** |
| G-PCC の幾何 + 本手法の属性 | 幾何由来 | 25.363 / 7.434 / **32.889** | **33.307** |
| LASzip 単体 | 取得順 | 22.219 / 9.422 / **31.641** | **32.482** |
| **LASzip + 本手法** | 取得順 | 22.219 / 7.434 / **29.653** | **30.224** |

すべて実測値であり、全点で復元照合している（見積もりの行は無い）。

```
本手法 対 LASzip   −6.3%（200万点） / −7.0%（800万点）
本手法 対 G-PCC    −22.3%           / −21.6%
組み合わせ 対 本手法  +10.9%          / +10.2%（いずれも悪化）
```

全 18 フィールドを通した場合（同一点数での対照）

| 点数 | LASzip + 本手法 | G-PCC の幾何 + 本手法 | 差 |
|---|---|---|---|
| 200万 | 52.773 bpp | 72.410 bpp | +37.2% |
| 800万 | 53.467 bpp | 73.979 bpp | +38.4% |

800万点では完全に重複する座標が 2 点あった。両側の Morton 順が与える座標列は
完全に一致し（ずれ 0 点）、重複点どうしの並びだけが幾何から決まらない。
照合は座標と属性の組の多重集合で行っている。

## 結論

**組み合わせは損である。** 見積もりの前提だった「G-PCC の幾何が良い」が、
私が入力に加えた Morton 整列の産物だった。
取得順のままなら LASzip の幾何が 12.4% 良く、
さらに全フィールドを通すと取得順依存の属性が壊れる分だけ差が開く。

得られたものは 2 つある。

1. **既報の比較表が LASzip を不当に不利にしていた。** Morton 整列は LASzip の幾何を
   27% 悪化させ、G-PCC を有利に見せていた。訂正後、本手法の対 G-PCC の優位は
   6.5% から 22.3% に広がる（我々に有利な方向の訂正だが、前の数字が誤りであることに
   変わりはない）。
2. **取得順と幾何由来順序は排他ではない。** 本手法の設計は、容器を取得順に保ったまま
   残差ストリームだけを幾何由来順序にする。この「両方使う」構成が効いている理由が、
   組み合わせを試したことではっきりした。

## 限界

- 比較は幾何 + 色 3 成分に限られる。G-PCC が運べないフィールドが元ファイルの
  55.5% を占める。
- G-PCC の幾何を取得順と比べる意味について異論はありうる。
  G-PCC はそもそも順序を保存しないので、順序を必要とする用途では選択肢に入らない。
  順序を必要としない用途でのみ、上の表の比較が意味を持つ。
