# 外の研究はどこを攻めているか（2026-09-22 の調査）

いまの設計族が模型として限界に近いと分かったので、外を広く見た。
**結論を先に書く: 我々が解いている問題を解いている研究が見当たらない。**
性能で先を行かれている部分は明確にあるが、それは**もっと易しい問題での数字**である。

## 1. 分野の主流 — 学習した文脈模型

可逆の幾何圧縮は、ここ 2 年で学習模型がほぼ制覇している。

| 研究 | 年 | 相手と数値 | 前提 |
|---|---|---|---|
| [Towards Practical Lossless Neural Compression for LiDAR](https://arxiv.org/abs/2603.25260) | 2026 | **G-PCC 八分木に −21.9%** | 幾何のみ／Morton 順／102.5M パラメタ／RTX 4090 で 14 FPS |
| [PACE](https://arxiv.org/pdf/2605.01320) | 2026 | 因果でない文脈（post-causal） | LiDAR 向け／学習必須 |
| [Next Bit Prediction](https://pubmed.ncbi.nlm.nih.gov/41489963/)（TPAMI） | 2026 | 可逆と非可逆を占有率の次ビット予測で統一 | 八分木の占有率 |
| [LINR-PCGC](https://arxiv.org/pdf/2507.15686) | 2025 | 陰関数表現で可逆 | 幾何のみ |

**注目すべきは 2603.25260 の「integer-only inference」**である。浮動小数の非決定性が
**符号化器と復号器で確率を食い違わせて復号を破綻させる**（entropy-coding collapse）
という問題が分野で認識され、8 bit 整数の演算・32 bit 固定小数の活性・表引きの
softmax で決定的にしている。**我々が「決定性 = バイト一致」で守ってきたのと同じ問題**を、
学習模型の側から解いた形である。

## 2. LASzip を直接の相手にしている唯一の研究

[LiZIP](https://arxiv.org/html/2603.23162)（2026）が **LASzip 比 −7.5〜14.8%** を報告している。
こちらの **−13.9%** と並ぶ数字だが、**前提が違う**。

| | LiZIP | PCC2（我々） |
|---|---|---|
| 可逆性 | **非可逆**（先に格子へ丸める。最大 0.011 mm） | **ビット完全** |
| 対象 | 幾何 (x,y,z) のみ | **全列＋VLR＋EVLR＋ヘッダの欄** |
| 点の順序 | **Morton 順に並べ替え（捨てる）** | **保つ** |
| 模型 | 学習済み MLP 540 KB が必須 | 不要（自己完結） |
| 速度 | CPU で符号化 118 ms / 復号 74 ms | — |

**「LASzip より 14.8% 小さい」と「LASzip より 13.9% 小さい」は同じ意味ではない。**
向こうは幾何だけを、順序を捨てて、丸めてから測っている。

## 3. 集合と系列 — 我々が突き当たった壁の理論的な枠組み

[Point Cloud Compression with Bits-back Coding](https://arxiv.org/abs/2410.18115)（2024）と
Random Cycle Coding が、**「集合を逐次符号器で送ると log n! が浮く」**という
bits-back の枠組みを点群に持ち込んでいる。

これは我々が測定で突き当たったことの裏返しである。**集合しか送らない相手（G-PCC）と
系列を送るこちらを bpp で並べてはいけない**という主張に、理論的な裏づけがある。
逆に言えば、**順序が要る限り H(順序|集合) は必ず払う**ことも同じ枠組みが言っている。

## 4. 我々の立ち位置

**誰もやっていないこと（調査した範囲で）**
- ファイル**丸ごと**のビット完全な往復（点の全次元・VLR・EVLR・ヘッダの欄）
- **元の点の順序を保つ**（LiZIP も学習 SOTA も Morton 順に並べ替える）
- **学習済み模型に依存しない**自己完結の器
- LiDAR の**属性**（強度・分類・戻り番号・波形）の可逆圧縮の比較。
  文献の「属性」はほぼ色（密な物体点群）で、我々の −17.3% に相当する比較対象が無い

**先を行かれていること**
- 幾何の符号長。学習模型は G-PCC 八分木に −21.9%。こちらは同等（0.98x）。
  ただし向こうは順序を捨てている

## 5. 取り込めそうな考え（我々の制約の中で）

制約: ビット完全／自己完結（学習模型を持たない）／決定的／CPU で実用速度。

**(a) 粗い層を先に送って文脈にする（PACE の post-causal、NBP の多段）**
いまの符号器は**格納順に厳密に因果的**で、各点は「それまでに復号した点」しか見ない。
八分木系は逆に「粗い解像度の占有率」を先に確定させ、それを細かい層の文脈にする。
**学習模型なしでも実装できる。**我々の逐次符号器に、
「まず各点の座標の上位ビットを全点ぶん送り、それを文脈に下位ビットを送る」
という二層構成を入れるのが最小の形。**いちばん本命。**

**(b) 多尺度の占有率を文脈に（cross-scale feature propagation）**
2603.25260 の 2 つの module のうち、学習に依らない部分の考え方。
点を符号化するとき、その点の粗い升の近傍がどれだけ埋まっているかを文脈にする。
(a) の二層構成が入れば自然に使える。

**(c) 整数だけの推論（integer-only inference）**
いつか学習模型を入れるなら、8 bit 整数演算・32 bit 固定小数・表引き softmax という
処方箋が既に公開されている。**我々の決定性の要件と両立する。**
ただし自己完結を捨てることになる（540 KB〜数百 MB の模型を配ることになる）。

### なぜ外れたか

**見積りの比較相手が弱すぎた。**Python の見積りでは「直前の値からの差」を外挿の
代表にして −13.0% と出たが、実際の符号器は AHN3 で `幾何v4W16記`（直近 16 点のうち
最も近い点から予測）を使っており、23.279 対 私の外挿 28.879 と 19% 良い。
**内挿の実装自体は見積りより良い**（26.263 < 見積り 26.984）ので、実装は正しい。

**より深い理由。**AHN3 の勝者が 幾何v4 だということは、**格納順が滑らかな曲線では
ない**ということである。格納順に沿って前後で挟んでも、空間的に近い点が
そこにあるとは限らない。持ち上げ変換は「系列が滑らか」を前提にしており、
LiDAR の格納順はその前提を満たさない。

### 文献の手法との構造的な違い（重要）

八分木系が空間的な文脈を使えるのは、**既知の格子の占有率を符号化している**からで
ある。占有率は「どの升に点があるか」であり、格子は最初から両側が知っている。
こちらは**与えられた順序で点の位置そのものを送る**ので、その点の位置を復号する前に
空間的な近傍を引くことができない。

**この非対称は順序を捨てない限り解けない。**文献が一様に Morton 順へ並べ替えて
いるのは、性能のためだけでなく、**空間的な文脈を使えるようにするため**である。
