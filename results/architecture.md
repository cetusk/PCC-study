## 0. 一言で

**列ごとに、符号器の候補を実際に符号化して、いちばん短いものを採る。**
恒等候補（`raw64`）をどの列にも混ぜてあるので、どの列も自前の符号器の中では
恒等より長くならない。**幾何を属性より先に復号する器**なので、属性の予測子は
座標を副情報なしで使える。点の順序は並べ替えない（取得順そのものが情報である）。

（例外: `--fast-attr` では前置きの 3 列の候補が `delta` と `ctx` だけになり、恒等が消える。）

**実測でなく推定で切り落とす所が 2 つある** — 幾何の予備選別（§7）と、属性の参照先の絞り
（`XKEEP = 4`、§5.3）。2026-09-24 に 3 か所とも損を測り（`losses.md` §34）、いまの設定では 15 件で
損が出ない（予備選別の取りこぼしは勝った族の測り直し 4 本で、参照先は 4 本で取れる。非可逆の格子は
実測で選ぶようにした）。それ以外は符号化した長さで決める。旗の重ね方は貪欲だが、全組合せを測っても
15 件合計 −0.006% しか縮まない（§7）。

## 1. 全体の流れ

```
入力（.las / .laz / .bin / .ply）
  │
  ├─ 1) 器を読む            las.cpp（LAS/LAZ・PLY）/ frame.cpp（KITTI .bin）
  ├─ 2) 格子を見つける       grid.cpp                → float を可逆に整数化   〔.bin/.ply だけ〕
  ├─ 3) 正規化              normalize.cpp analyze() → 計画（落とす列）      〔LAS だけ〕
  ├─ 4) 列に並べ替える       frame.cpp               → Frame（列 + スキーマ + 封筒）
  ├─ 5) 粗い格子で割る       frame.cpp apply_column_grid → coldiv          〔LAS だけ〕
  ├─ 6)〔非可逆〕量子化      main.cpp --eps + geom.cpp → 既定では通らない（§10）
  │
  ├─ 7) 流れを計画する       pcc2.cpp plan_streams   ← 本体
  │      列ごとに候補を並べ、符号化して最短を採る（§5〜§7）
  │
  └─ 8) 器に書く            pcc2.cpp write_pcc2     → .pcc2（§9）

unpack は 8→1 を逆にたどり、--las なら元の LAS/LAZ を、--bin なら KITTI の .bin を書く。
```

**3 が 4 より先なのはメモリのため。**計画を先に立てれば、残す列だけを
`PointCloud` から**移して** `Frame` に渡せる（逆順だと同じ中身を二重に持つ瞬間ができる）。

### pack の後半 — 書いてから確かめる

```
  書く          <出力>.part に書く（検証が通るまで本来の名前にしない）
  退避路         自前の出力より、書き直した基準 LAZ のほうが短ければそれを包む
  決定性         選ばれた流れを、選択で温まった表を持たない新しい文脈で符号化し直して
                 バイト列を比べ、同じ流れを器に書き直しても比べる（食い違えば戻り値 2）
  復号           .part を読み、列を戻す
  照合 1         元のファイルを読み直し、全列を突き合わせる（非可逆なら幾何は誤差上限の中）
  照合 2         unpack --las と同じ道で書き戻し、元のファイルと「器として」比べる
                 （点の全次元・ExtraBytes・VLR/EVLR・ヘッダの欄・ユーザーデータ）
                 LAS の入力を可逆で、照合 1 が通ったときだけ
  確定           決定性・照合 1・2 が通ったら .part を本来の名前に移す。
                 落ちたら何も残さない（戻り値 2。復号や読み直しの失敗は戻り値 1）
```

**決定性の検査は 2026-09-23 に作り直した。**以前は流れを器に書き直して比べるだけで、
符号器を走らせ直さず、食い違っても止めなかった（`defects.md` §7）。いまは符号器の
決定性を確かめるが、**候補の選択そのもの**（どの候補が勝つか）の決定性は見ない。
そちらはスレッド数を変えた md5 の一致（§12）で見る。費用は 15 件の中央 200 万点の合計で
再符号化 4.30 s（符号化 52.61 s の 8.2%。`enc` の外で、pack 全体の時間に乗る）。

照合 2 は 2026-09-23 に足した。照合 1 は列しか見ないので、封筒（ヘッダの欄や
未記述のバイト）の欠落を素通りさせていた（`defects.md`）。
`--no-verify` は決定性・復号・照合を全部飛ばす。三者比較・内訳のベンチ
（`bench_three` / `bench_split` / `bench_size`）は `--fast-attr` と一緒にこれを付け、
検証は `python/verify_suite.py` で別に回す。§14 の速度とメモリの出所 `bench_all.py` は
付けていない（符号化時間は pack が表示する検証を含まない enc、ピークは検証込みのプロセス全体）。

## 2. 入力側

### 2.1 器を読む

| 器 | 経路 | 備考 |
|---|---|---|
| `.las` / `.laz` | `las.cpp`（LASzip の C API） | 版 1.0〜1.4、点形式 0〜10。EVLR と 1.3 の波形データは LAS を直に読む。1.5 は断る |
| `.bin`（KITTI） | `frame.cpp` の `load_kitti` | float32 × 4（x, y, z, 強度）。長さが 16 byte の倍数でなければ断る |
| `.ply` | `las.cpp` の `read_points_any` | ascii / binary、整数と浮動小数の各型。頂点が最初の要素で list を持たないものだけ |

**LAS では、運ぶものは「読めた列」ではなく「元のファイルを再現できるもの」全部。**
点の次元・VLR・EVLR・ExtraBytes の配列型と記述されていない余りのバイト・
波形パケットの 29 byte・LAS ヘッダの欄・ユーザーデータを、列と封筒（§9）に分けて持つ。
**PLY は x/y/z だけを読み、色や法線は捨てる。**`unpack` も PLY を書き出す口を持たない
（出せるのは `--las` と `--bin`）。

**ヘッダの範囲・点数・戻り番号ごとの点数は、読み込み時に中身から数え直し、元の値と
食い違う欄だけを封筒に載せる**（大半のファイルは 1 byte も増えない）。GUID と
波形データの位置は数え直しと関係なく、0 でなければ載せる。書き出しでは、範囲は元の値を
そのまま LASzip に渡し、点数の欄は数え直した値を渡して、閉じた後に元の値で上書きする
（LASzip は食い違う点数では書き始めを拒むため）。波形データの位置は、書き直した
ファイルでの EVLR の位置に置き換える。

ExtraBytes の名前が標準の列名（`X` や `intensity`）や別の ExtraBytes とぶつかるとき、
または空のときは、列の名前を `eb<番号>:<名前>` にする（さらにぶつかれば
`eb<番号>_<t>:<名前>`。器の中の名前は元のまま）。

### 2.2 float の座標を整数に直す（`grid.cpp`）

点群を float で持つ器は、中身が整数のことがある。**候補は統計で探し、採否は
ビット単位の証明で決める** — 刻み `s` について全点で元のビット列が再生できることを
確かめ、1 点でも再生できなければ採らない（`-0.0` だけは符号が消えるので位置を別に覚える）。
道は `round(v/step)` と、十進の文字列から来た値のための `round(v*10^d)` の 2 本。

KITTI の `.bin` では 1 mm 格子が見つかり、108 frame の中央値で **21.367 bpp**
（素の float32 × 4 = 128 bpp に対して −83.3%）。これは整数化を含めた符号化全体の値。

### 2.3 列が粗い格子に乗っていたら割る（`apply_column_grid`）

宣言された分解能が実際の分解能とは限らない（8 bit の色を 16 bit 欄に入れた LAS など）。
整数の列は**値の絶対値の最大公約数**で割り、商は符号つきで持つ。実数の列（ビット列を
整数として持つもの）は最小値を引いてから割る。幾何を割ったときは scale/offset も合わせて
動かすので、世界座標は変わらない。割った後の幅が 1 以下の列は割らない（刻みを書くぶん損）。

### 2.4 正規化（`normalize.cpp`）

フィールド名をハードコードせず、**列どうしの関係をデータから見つける**。

| 種類 | 何をするか |
|---|---|
| `drop_constant` | 定数列を落とす（値だけ計画に残す） |
| `drop_duplicate` | 同一の列を落とす |
| `drop_affine` | `b = num/den * a + b0` が全点で成り立つ列を落とす（128 bit で検出・復元） |

採用は全点で成り立つものだけ。計画は二値で器に入る（二値で 4 byte 以上縮まなければ JSON のまま）。
LAS の入力だけに掛かる（KITTI・PLY の列は x/y/z と強度だけなので要らない）。
**前に出す 3 列（`point_source_id` / `gps_time` / `bit_fields`）は落とさない**（§4）。
概ねの関係は符号器側の `参照<列>`（§5.3）が実測で拾う。

## 3. 列と Frame

`Col` は「基準 + 詰めた符号なし整数」。幅は値域から 1/2/4/8 byte を選び、定数列は 8 byte で済む。
`Frame` は名前で引く列の地図と、出現順のスキーマ（元のファイルの列の並び）と封筒を持つ。
各列は `Raw`（そのまま）/ `Derived`（計画から復元）/ `Residual`（他の列との残差）のどれか。

## 4. 流れの順序 — なぜ `gps_time` が幾何より前か

符号化側は**既に出した列しか参照しない**ので、先に置いた列は後の列の予測に副情報なしで
使える。この一点が構成全体を決めている。（復号器は流れの依存 — param に書いた列名と、
光の旗なら `bit_fields` — から波を組んで並列に戻す。）

```
1) point_source_id, gps_time, bit_fields     ← 走査モデルと戻りの種類が要る 3 列
2) X + Y + Z                                  ← 幾何（3 軸まとめて 1 本の流れ）
3) それ以外の属性                              ← 座標が揃っているので空間予測が使える
```

- **1 を前に出す理由**: 走査モデルは飛行線と掃引を組み直すのに時刻と線番号が要る。
  `bit_fields`（戻り番号と戻り総数）は、後ろの幾何と属性の「光」の文脈（§6）に使う
- **代償**: 前の 3 列自身は空間予測を候補に持てない（座標がまだ無い）
- **属性は後ろ**: `intensity` は `point_source_id` を文脈にでき、座標も使える

**点の順序は並べ替えない。**Morton 順に並べ替えた複製を同じ符号器に通すと、全列で
15/15 が伸び、比の中央値で +25.9%（USGS AK の `gps_time` は 3.066 → 19.168 bpp）。
順序は代償ではなく資産である。（2026-09-22 の測定。`results/orderfree.md`、
`data/work/orderfree/morton_all.log`）

## 5. 符号器

### 5.1 汎用の符号器

属性の列には下の 10 種が全部出る（`素<幅>B` は前置きの 3 列を除く）。幾何（`X+Y+Z`）に出るのは `raw64` / `素4B` / `range` /
`delta` の 4 つだけで、残りは §5.2 の幾何専用の系統が受け持つ（基底は 58 本）。

| id | 名前 | 中身 |
|---|---|---|
| 0 | `raw64` | **恒等候補。**1 値 64 bit |
| 13 | `素<幅>B` | 列の自然な幅でそのまま（1 byte の列の天井。幾何より前の 3 列には出ない） |
| 1 | `range` | zigzag + レンジ符号 |
| 2 | `delta` | 1 次差分 |
| 3 | `ctx` | 1 次差分＋直前の差分の桁数を文脈に |
| 4 | `ctx2` | 2 次差分＋文脈（一定刻みの列） |
| 5 | `med3` | 直近 3 差分の中央値を予測子に（幾何v1 と同じ符号器） |
| 6 | `差分表` | 直近 K 個の相異なる差分の表を指す |
| 7 | `直前` | 値そのものを、直前の値を文脈に（1,2,3,1,2 と繰り返す詰め込みビット） |
| 8 | `字母` | 値の種類が少ない列を、字母のまま直前の記号を文脈に送る。既出の列も文脈に使える |

### 5.2 幾何（3 軸まとめて 1 本）

文脈は**残差の桁数**で作り、後の軸は前の軸の桁数も見る。

| id | 名前 | 中身 |
|---|---|---|
| 9 | `交差軸` | 3 軸を順に送り、後の軸の文脈に前の軸の差の桁数を使う |
| 10 | `幾何v0`〜`幾何v4` | `param[0]` で系統が変わる（下） |
| 11 | `走査v1`〜`走査v4` / `走査変換`（v5） | ALS の走査モデル（`scanmodel.cpp`）。飛行線と掃引を当てはめる |
| 12 | `向き<予測子>` | y をその点の `dx` から予測する |
| 15 | `回転<予測子>` | 主成分に座標系を合わせる。**せん断 3 回で整数のまま可逆** |

- `幾何v0` — 軸ごとに独立（`enc_cols`）
- `幾何v1` — 直近 3 差分の中央値（`enc_geom_med`）
- `幾何v2` — 予測子の状態を補助列ごとに分ける（`enc_geom_aux`）
- `幾何v3` — 軸をまたぐ文脈（`enc_geom_x`）。予測子と文脈の粗さ、補助列を選べる
- `幾何v4` — 直近 W 点の最近傍から予測（`enc_geom_w`）。格納順が空間的に飛ぶ入力に効く

予測子は 8 通り（med3 / avg4 / 半分 / med5 / 四半 / 三四半 / 無傾 / med5半）。
回転の係数は流れの先頭に整数で書く（三角関数を復号側で計算すると桁が食い違うため）。

### 5.3 属性

| id | 名前 | 中身 |
|---|---|---|
| 20 | `sp(P=k)` | 幾何由来の順序で先行する近傍 P 個から予測（P = 1/3/5） |
| 21 | `色` | 3 列に可逆色変換を掛けてから同上 |
| 22 | `参照<列>` | 既に復号済みの別の列との残差（差分のまま、空間予測をかけて、または差にさらに格納順の 1 次差分を掛けて） |

`参照<列>` の相手は見積りで絞る: 差のエントロピーの上位 `XKEEP = 4` 本と、空間予測後の
エントロピーの上位 4 本を合わせて重複を除く（最大 8 本）。前置きの 3 列は、先に出た前置き列を
全部相手にする（絞らない）。色は「まとめて 1 本」「汎用の 3 本」「blue → green → red の鎖
（直前の色を相手に）」の 3 通りを測って最短を採る（幾何が揃っているときだけ）。

## 6. 文脈と旗（符号器 id に重ねる）

旗は符号器 id の上位ビットに重ね、流れの表に書く。復号側は id を見て同じ文脈を組む。
**旗は、それを読む符号器にだけ試す**（読まない符号器に立てても同じ長さになる）。
`字母` は `FreqModel` しか使わず記・生・束を読まないので、記号版の対も生の版も作らない
（2026-09-23 まで作っていた。外して出力は 15/15 でバイト一致のまま、符号化 −4.2〜−7.9%）。
速 の選び直し（§7）だけは全候補に 速 を付けるので、恒等・素の幅・字母にも付くが、
勝者を変えない（それらは選び直す前の勝者より短くなりえない）。

| 旗 | 名前 | 何をするか | 読む符号器 |
|---|---|---|---|
| `0x8000` | 記 | 桁長と下位ビットを 1 記号ずつ送る | UIntCoder を使う全部 |
| `0x4000` | 生 | 仮数部の下位を模型に通さず素通し（一様なビットに適応模型は害） | 同上（恒等・素の幅を除く） |
| `0x1000` | 束 | 文脈ごとの表が温まるまで全文脈に共通の表 | 記号版 |
| `0x0800` / `0x0400` | 符1 / 符2 / 符4 | **直前の残差の符号を 1 / 2 / 4 個**文脈に足す（桁数の文脈は符号を捨てるので） | 幾何v0/v1/v3/v4・回転・向き・走査（全 var）、属性の差分・文脈つき差分・ctx2・med3・参照・空間予測・色 |
| `0x0200` | 光 | 幾何v3/v4・回転: **同じパルスの続きの点**に別の文脈を割り当て、傾きの履歴に入れない（続きの点が 1 つでもあるときだけ試す）。それ以外: 点ごとの**戻りの種類**（単独・複数の最初・最後・中間）を文脈に足す（戻り総数 2 以上の点があるときだけ試す） | 幾何v3/v4・回転（続きの点）、幾何v0/v1・向き・med3 と属性の残差符号器（`range`・ctx2 を含む。戻りの種類。空間予測は順序表で点の番号に引き直す） |
| `0x0100` / `0x0080` | 面6 / 面7 / 面8 | z を (x, y) の近くの復号済みの点からも予測し、直近の成績で予測子を切り替える | 幾何v4 |
| `0x0040` | 速 | 二値の模型の速さの表を「後半 1/32」に替える（§8） | 二値の模型を使う全部 |
| `0x0020` | 類 | **既に復号済みの別の列の値を 4 つの類に分け**（値の種類が 64 以下なら出現の多い上位 3 値とその他、多ければ 4 分位）、文脈に足す。相手は属性なら前置きの列と先に出る属性（色の 3 列どうしは除く）、幾何なら前置きの列と gps_time の差（`Δgps_time`）。列名を param の末尾に付ける | 光を読む属性の符号器と `字母`（文脈に掛け合わせる）、幾何v0/v1・向き・走査 var 1/2/5（光とは併用しない） |
| `0x2000` | 照 | 桁長の照合模型。**候補から外してある**（22 列で採用 0） | 記号版 |

光は `bit_fields` が前置き列（§4）のときだけ使い、前置き列そのものには付けない（循環する）。
復号側は光の流れの依存に `bit_fields` を足して、先に戻ってから復号する。

## 7. 選び方（`best_stream`）

```
候補を並べる（列の種類ごと。記号版の対も作る）
  │
  ├─ 予備選別（幾何だけ。点数が標本の 2 倍を超えるときだけ）
  │     先頭の連続した 2 万〜2.5 万点で順位を付けて上位 4 本に絞る。
  │     残した各候補のビット版と記号版の対、族（走査 / 空間 / 幾何v4 / 向き / 回転）×
  │     記号版の組ごとに 1 本、族に属さない記号版を 1 本、必ず残す
  │
  ├─ 全点で符号化（プールで並列。最短より長いと判ったものはその場で打ち切る）
  │     勝った族の控えを最大 4 本、全点でまとめて並列に測り直す
  │
  ├─ 後置検査 1 段目: 勝者に旗を重ねた版をまとめて並列に測る
  │     生 / 束・生＋束（勝者が記号版のとき）/ 符1・符2・符4 / 光・光＋符1/2/4 /
  │     類<列>・類<列>＋符1/2/4（相手の列ごと）（§6 の「読む符号器」のときだけ）
  ├─ 後置検査 2 段目: 勝者に 面6 / 面7 / 面8（幾何v4 のとき）
  ├─ 後置検査 3 段目: 勝者に 速 を重ねた 1 本
  │
  ├─ 速 が勝ったら、全候補に 速 を付けて選び直し、短いほうを採る
  │     （既定の表で比べると、場面の変わるデータでは選ばれる候補そのものが変わるため）
  │
  └─ いちばん短いものを採る（同じ長さなら添字の早いほう）
```

- **後置検査を勝者だけに限る理由**: 打ち切りは候補が終わる順で効くので、順位表に残る候補は
  スレッド数で変わる。勝者は打ち切りに依らず決まるので、勝者だけに重ねれば決定的である
- **`--force-geom <名前>`** は幾何の候補を 1 本に固定し、その流れには旗を足さない。
  旗つきの名前（`幾何v1符1光` など）も指定できる。選ばれなかった候補を往復させるのに使う。
  一致する名前が無ければ誤りにせず、ログに一言残して全候補で選ぶ
- **`--sample-select <n>`** は選択そのものを標本で行い、全点では勝者と控えだけを測って、
  後置検査 1〜3 段を掛ける（速 の選び直しはしない）
- **旗の重ね方は貪欲**: 1 段目は勝者にだけ、面 は 1 段目の勝者にだけ、速 は 2 段目の勝者に
  だけ試す。全組合せ（`PCC_POST_ALL=1`。類の候補は含まない）を測っても、15 件合計 −0.006% に対し
  符号化 +395% だった（`losses.md` §34）
- **勝った族の測り直しは単調にしてある**: 控えは旗を重ねる前の長さで選ぶので、3 本目以降の控えで勝者が
  入れ替わったときは、入れ替わる前の勝者にも旗を重ねて測り、重ねた後の長さで短いほうを採る

符号化器だけに効く選択肢（器の読み方は変わらない）: `PCC_ATTR_SGN=0`・`PCC_ATTR_RAY=0`・
`PCC_FAST=0`・`PCC_FAST_RERUN=0`・`PCC_FAST_RERUN_MIN=<‰>`・`PCC_ATTR_SGN_STAGED=1`・
`PCC_CLS=0`（類を試さない）・`PCC_CLS_GEOM=0`（幾何に類を試さない）・`PCC_XREF_KEEP=<本>`（既定 4）・
`PCC_FAMALT=<本>`（勝った族の測り直し、既定 4）・`PCC_LATTICE_MEASURE=0`（非可逆の格子を代理で選ぶ）。
`PCC_CLS_MAX=<本>`（類の相手の列の数の上限）。0 にする・減らす向きはどれもサイズを失う代わりに速くなる
（`losses.md` §27〜§34）。測るための `PCC_POST_ALL=1`（旗の全組合せ）と
`PCC_GEOM_KIND=<種類>`（非可逆の格子を固定）もある。

## 8. エントロピー符号器（`rangecoder.hpp`）

```
Encoder / Decoder      LZMA 方式のレンジ符号（整数演算だけ）
  ├─ BitModel          2 値。出現回数（255 で止める）で寄せる速さ 2^-r を変える:
  │                      回数 0,1,2,3,4〜7,8〜15,16〜31,32〜63,64〜127,128〜 に
  │                      既定  r = 1,2,2,3,3,4,5,6,6,7（出現の少ない文脈は速く、長く続いたら遅く）
  │                      旗 速 r = 1,2,2,3,3,4,5,5,5,5（後半を 1/32 のまま。場面の変わる流れ向け）
  │                    旧形式の器（PCC1）は 1/32 固定のまま（Python 実装とバイト一致）
  ├─ FreqModel         多値。総和の 1/32 ぶん重みが加わるごとに表を作り直す
  └─ UIntCoder         非負整数 = 桁長 k + 下位 k ビット
       ├─ 既定          k を単項、下位をビットごと
       ├─ 記（FSYM）    k を 1 記号、k ≤ 8 なら下位も 1 記号
       ├─ 生（RAWKEEP） 下位の上から 1 bit だけ模型に通し、残りは素通し
       └─ 束（BUNDLE）  文脈の観測数が 24 に届くまで共通の表
```

既定では桁長と下位ビットに同じ文脈を使う。分けるのは幾何v3 の `param` に 64 のビットが
立った変種（候補 `{3,64}` `{3,66}` `{3,70}` `{3,82}`）だけで、下位ビットは粗い文脈を共有する
（`encode2`）。二値の模型を 2 つ持って平均する形は試して外した（§13）。

## 9. 器の形（`.pcc2`、版 5）

```
"PCC2" + 版（5。読み方が変わるたびに上げる。版 3・4 も読み、それより古い版ははっきり断る）+ 精度の旗（u16）+ 点数（u64）
タグつきの頭（順不同・未知のタグは読み飛ばせる）
  1 出所の種類   2 元のバイト数   3 scale   4 offset   5 スキーマ
  6 正規化の計画 7 精度の申告     8 封筒    9 幾何の列名 10 幾何の表し方
  11 包んだ器     12 粗い格子      13 極座標格子
流れの表（列 → 符号器 id（旗つき）+ param + 長さ）
流れの本体（連結）
crc64
```

**封筒（LAS の場合）**: 点形式・レコード長・版・ExtraBytes の定義・ヘッダの欄
（ファイル識別子・作成日・ソフト名など）・ExtraBytes の VLR の元のバイト列・VLR・EVLR。
末尾は「札つきの拡張」で、**既定の値と同じものは書かない**:

| 札 | 中身 | 書くとき |
|---|---|---|
| 1 | ExtraBytes の VLR の元の位置 | 先頭以外にあったとき |
| 2 | 中身から数え直した値と食い違う欄（範囲・旧形式と拡張の点数・戻り番号ごとの点数）と、0 でない GUID・波形データの位置 | 載せる欄があるとき |
| 3 / 4 | ヘッダの中・直後のユーザーデータ | あるとき |
| 5 | ExtraBytes の VLR に記述されていない次元の番号 | あるとき |

KITTI / PLY の封筒は、見つけた格子（刻み・十進の道・`-0.0` の位置）を持つ。

**包んだ器（タグ 11）**: 自前の出力より、書き直した基準 LAZ のほうが短いときに、
その中身を包んで運ぶ退避路（LAS の入力だけ）。ベンチは `--no-fallback` で切っている。

**壊れた器は落ちずに断る**: 長さは残りと比べてから進み、本数は器に収まる上限と
比べてから配列を取る。復号の糸の例外は理由として持ち帰る（`defects.md`）。

## 10. 非可逆の枝（`pack --eps <m>`、既定では通らない）

浮動小数の座標を持つ器（`.bin` / `.ply`）にだけ使える。

```
世界座標 → choose_geometry（geom.cpp）
             ├─ 極座標格子（回転式 LiDAR） → geom_repr = "polar"
             └─ 粗いデカルト格子           → geom_repr = "int"（封筒の可逆の格子は外す）
           → 以降は可逆の経路と同じ
```

**格子の種類は、幾何の流れを実際に符号化した長さで選ぶ**（2026-09-24 から）。直交・原点中心の極座標・
重心中心の極座標の 3 種類それぞれで誤差上限を守る刻みまで詰め、幾何だけの計画を立てて短いものを採る
（比べる 3 回と本番を合わせて、非可逆の経路の幾何の計画が最大 4 回になる）。代理の符号長（先頭 20 万点を汎用の圧縮器に通した長さ）で
選んでいたときは、KITTI の 2 mm で 68 件中 3 件を取り違えていた（`losses.md` §34）。`PCC_LATTICE_MEASURE=0` で
代理の選択に戻す。候補ごとの長さは `PCC_GEOM_VERBOSE=1` で表示できる。TLS の講堂のスキャンでは極座標
（スキャナ中心）が直交格子より 38〜43% 短い（`tls_lattice_v22.log`）。

**誤差は利用者が受け取る値で測る**（復号と同じ道で格子に戻し、float32 に丸めてから比べる）。
超えたら刻みを詰めて測り直す。検証は「属性はビット完全、幾何だけ誤差上限の中」。

| 誤差上限 | KITTI 20 frame 中央値 bpp | 可逆比 |
|---|---|---|
| 可逆 | 21.506 | — |
| 2 mm | 18.017 | −16.2% |
| 5 mm | 14.233 | −33.8% |
| 20 mm | 10.169 | −52.7% |
| 0.1 m | 7.462 | −65.3% |

（`lossy_v24.log`）KITTI は、代理の見積りで選んでいたときは 2 mm〜0.1 m のどれでも極座標格子だった（20 frame × 誤差上限 5 通りで 100/100、
`lattice_kind_v21.log`）。実測で選ぶようにしてからは、2 mm で 20 frame 中 3 frame が直交格子になる（`lattice_loss_measured_v22.log`）。
TLS の PLY も極座標、物体のスキャン（Armadillo・bunny の PLY）は粗いデカルト格子が選ばれる
（`lattice_kind_v21.log`）。極座標の復号は自前の sin/cos を通る（§11）。

## 11. 並列・メモリ・決定性

- 計画の間だけ生きるプールを 1 つ建て、**列の仕事も候補の仕事も同じ待ち行列に流す**
  （列を 1 本ずつ回すと、候補が終わりかけで機械が空く）
- 空間予測の近傍表は、幾何の列を符号化している裏で作っておく
- 最短より長いと判った出力はその場で捨てる
- **糸ごとの状態**（旗・文脈の切り替え・速さの表）は符号器の入口で設定し、抜けるときに戻す
- **復号は実験用の環境変数を読まない**（常に既定値）。pack は復号に効く実験用の変数が
  設定されていると断る（`PCC_ALLOW_EXPERIMENT=1` で測るためだけに通せる）
- 列の仕事や候補の例外は失敗として扱い、壊れた器を書かない
- コンパイルは `-fwrapv`（符号つき整数の桁あふれを折り返しと定める）と
  `-ffp-contract=off`（掛け算と足し算を 1 命令にまとめない）。符号器と復号器が別の最適化で
  走っても同じ値になるようにするため
- **命令セットは既定で `x86-64`（SSE2 だけ）**。native（この機械の AVX-512 まで）で建てた
  二値と、15 件・KITTI 20 frame × 3（可逆・5 mm と 0.1 m の極座標）・PLY 4 件・TLS の PLY の
  極座標・Armadillo のデカルト格子の 81 件で器の md5 と相互の復号が一致した（`isa_v24.log`、verify_suite の isa）。x86-64 のほうが符号化は遅くない（交互 3 回で
  −8.5%、`ab_native_x86_v20.log`）ので既定を替えた。**x86 以外（ARM など）は測っていない**
- **復号は libm を通らない**（十進の格子の 10^d は正確な定数の表。走査モデルの角度は
  整数の CORDIC、回転の係数は整数で器に入る。非可逆の極座標は四則演算だけで組んだ sin/cos
  （`dettrig.hpp`）で戻す）。極座標の座標は空間予測の順序表にも入るので、1 ulp のずれでも
  可逆の属性が戻らなくなりうる — 版 3 まではここが libm だった（`defects.md` §7）。
  版 3 の器は極座標だけ libm で戻す

メモリは 1 点あたり 928 byte（全列、200 万点。LASzip よりずっと重い）。幾何のみの三者比較でも
最も重い（G-PCC の 4.8 倍）。全点と、試している候補の出力を同時に抱えるためで、
削るとサイズを失う（`losses.md` §33）。

## 14. いまの成績（正本は `standing.md` §1）

| 指標 | 値 |
|---|---|
| 全列 対 LASzip | **−16.3%（15/15）** 四分位 [−32.9, −12.8] 幅 −38.2〜−9.8 |
| 幾何 / 属性 | −13.3%（15/15）/ −18.3%（15/15） |
| 幾何のみ 17 ファイル | 対 LAZ 0.87x（17/17）。対 G-PCC は素のままで 0.91x（11/17）、**順序の復元も含めた同じ仕事では 15/17 ＋ 2 件は決着せず**（`standing.md` §2.1.1） |
| 速度（200 万点） | 符号化 LASzip の 47.1 倍、復号 9.9 倍（どちらも遅い。比は LASzip の側で揺れる） |
| メモリ | 928 byte/点 |

**勝っている軸はサイズだけである。**速度は「候補を全部符号化して最短を採る」という
設計そのものに、メモリは全点と候補を同時に抱えることに由来する。
