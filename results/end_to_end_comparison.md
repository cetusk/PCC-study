# 端から端まで他手法と比べる — 幾何を含めた 3 方式の比較

## なぜ必要だったか

これまでの比較（`attribute_spatial_finding.md`）は**属性だけ**の比較だった。
看板の数字である「可逆で −28.5%」には他手法との対応が付いておらず、
表に並んでいたのは自分の実装どうしの切り分けにすぎなかった。

## 土俵を揃える

2 つの不公平を先に潰す。

**1. 内容の不一致.** G-PCC が運べる属性は色と反射率に限られる。
航空 LiDAR が実際に持つフィールドのうち、渡せないものは 12 個ある。

```
intensity, bit_fields, classification_flags, classification, user_data,
scan_angle, point_source_id, gps_time, nir, Amplitude, Reflectance, Deviation
```

これらは元ファイルの **55.5%** を占める（全フィールド 71.240 bpp に対し
xyz+rgb のみ 31.677 bpp、同一フォーマット・同一順序で測定）。
比較のために捨てている情報が半分以上あることは、明記しておく必要がある。
よって比較は「幾何 + 色 3 成分」に内容を揃えて行う。

**2. 順序の扱い.** G-PCC は点の出力順を保存しないが、LASzip は保存する。
順序の保存にはビットがかかるので、そのままでは LASzip が不利になる。
入力を **Morton 順に整列**させ、順序を幾何から復元可能にすることで、
3 方式が同じ情報を符号化する状態を作る。

## G-PCC で可逆になる設定は 1 つしかなかった

> **設定についての注記（`scan_model_fitting.md` 25 節）。** ここで使っている
> G-PCC の幾何 25.363 bpp は**無調整に近い設定**の値である。設定を 8 通り
> 振ると同じデータの同じ点数で 24.375（IDCM=2）まで下がる。
> 新しい比較では調整済みの値を使っているので、25.363 とは直接比べられない。


QP を振って全点照合した（AHN4 200万点、色空間変換なし）。

| 方式 | QP | 合計 | 色の不一致 | 最大誤差 | 判定 |
|---|---|---|---|---|---|
| RAHT | 0 / 1 | 符号化失敗 | — | — | — |
| RAHT | 4 | 38.104 b | 419,035 | 1 | **非可逆** |
| RAHT | 8 | 35.200 b | 1,518,651 | 3 | 非可逆 |
| 階層予測 | 0 / 1 | 符号化失敗 | — | — | — |
| **階層予測** | **4** | **38.143 b** | **0** | **0** | **可逆** |
| 階層予測 | 8 | 35.508 b | 1,375,352 | 1 | 非可逆 |
| 階層持ち上げ | 0 / 1 | 符号化失敗 | — | — | — |
| 階層持ち上げ | 4 | 37.508 b | 417,772 | 3 | 非可逆 |
| 階層持ち上げ | 8 | 35.348 b | 1,050,104 | 3 | 非可逆 |

**可逆なのは階層予測・QP=4 のみ。** 800万点でも同じ設定で可逆を確認した
（点数一致・座標不明 0・色の不一致 0）。

### 既報の訂正

`attribute_spatial_finding.md` の表で RAHT と階層持ち上げを
「可逆・誤差 0」と書いていたが、**誤り**である。
検証したのは階層予測だけで、他の 2 つは未検証のまま可逆と記していた。
実際には QP=4 でそれぞれ誤差 1 と 3 を出す。
したがって「G-PCC の最良は階層持ち上げ 11.513 bpp」も誤りで、
可逆の範囲での最良は階層予測である。

## 結果

AHN4、Morton 順に整列、幾何は可逆・色 3 成分は可逆、全点照合済み。単位 bit/点。

| 方式 | \_\_\_200万点\_\_\_ | | | \_\_\_800万点\_\_\_ | | |
|---|---|---|---|---|---|---|
| | 幾何 | 色 | 合計 | 幾何 | 色 | 合計 |
| G-PCC 階層予測 QP=4 | **25.363** | 12.780 | 38.143 | **25.694** | 12.879 | 38.574 |
| LASzip 単体 | 28.232 | 9.302 | 37.534 | 28.483 | 9.369 | 37.852 |
| **本手法 + LASzip** | 28.232 | **7.434** | **35.666** | 28.483 | **7.521** | **36.004** |

```
本手法 対 LASzip      −5.0%（200万点） / −4.9%（800万点）
本手法 対 G-PCC       −6.5%           / −6.7%
```

規模を 4 倍にしても順位も差も動かない。

## 分解すると、勝ち負けは分かれている

```
幾何   G-PCC 25.363  <  LASzip 28.232        G-PCC が 10.2% 良い
色     本手法 7.434  <  LASzip 9.302  <  G-PCC 12.780
                                            本手法が LASzip より 20.1%、
                                            G-PCC より 41.8% 良い
```

**G-PCC の幾何符号化は LASzip より 10% 良く、
本手法の属性符号化は G-PCC より 42% 良い。** 合計では相殺して本手法が 5〜7% 勝つ。

素直な帰結として、両者を組み合わせれば
```
G-PCC の幾何 25.363 + 本手法の色 7.434 = 32.797 bpp   （対 LASzip −12.6%）
                     800万点では             33.215 bpp   （対 LASzip −12.3%）
```
となるはずである。ただしこれは**足し算による見積もりであって、実測ではない**。
実際に組むには G-PCC の幾何ストリームと本手法の属性ストリームを
1 つの容器に収める必要があり、未実装である。

## 限界

- 比較は「幾何 + 色 3 成分」に限られる。元ファイルの 55.5% を占めるフィールドは
  G-PCC に渡せないため、この比較の外にある。
  実運用の圧縮率（−28.5%）はそれらを含んだ数字であり、この表とは別物である。
- Morton 整列は LASzip を大きく助ける。整列しない場合 LASzip の色は
  4 成分で 14.537 bpp（`attribute_spatial_finding.md`）だったが、
  整列後は 3 成分で 9.302 bpp、1 成分あたり 3.10 bpp まで下がる。
  本手法の優位（20%）は整列後の LASzip に対するものであり、
  整列前と比べると過大に見えることに注意。
- G-PCC は QP 0 と 1 で符号化に失敗した。原因は追っていない。
