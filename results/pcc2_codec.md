# 自前符号器 PCC2 — LAS/LAZ 非依存のコンテナと、LASzip を使わない符号化

> **履歴**（2026-09-23 の索引 `results/INDEX.md` による）: PCC2 の初回実測（09-19）。「現状の位置づけ」の数値はその時点のもの。**現在の数値は `results/standing.md`**。

測定日 2026-09-19。すべて `cpp/build/pccnorm pack` による実測で、
**毎回その場で復号して全列の完全一致を確認**している。通らなければ数字を出さない。
決定性は同じ入力を 2 回符号化してバイト一致を確認した。

## なぜ器から作り直したか

これまでの構成は LASzip の前段に入る正規化レイヤーだった。その形では

- 幾何 22.2 bpp（全体の 41%）が丸ごと LASzip のもので、こちらの寄与がゼロ
- 器が LAS の点形式に縛られ、KITTI・TLS・PLY を同じ土俵に載せられない
- 取得表現への復帰で得た表現（極座標格子など）を格納する場所がない

設計は `notes/02_codec_container.md`。要点は 3 つ。

1. **完全に自己記述的** — 復号に点数もスキーマも外から渡さない（PCC1 は渡していた）
2. **幾何も属性と同じ「列」** — 符号器を差し替えられる
3. **恒等符号器 RAW64 を必ず候補に含める** — 器の長さが有限で閉じる

採否はすべて**候補を実際に符号化して最短を採る**。推定は使わない
（`lossless_refinements.md` の 3.1 bit/点はこの置き換えだけで戻った）。

## 幾何符号器 — LASzip を超えるまで

超えるべき線は **LASzip の 22.219 bpp**（AHN4 200万点・取得順）。
既測の素朴な予測器は届いていない（1 次差分 25.292 / 2 次 25.875 / 3 次 28.876）。

4 つの版を実装して同じ土俵で測った（AHN4 200万点、全候補の実測値）。

| 版 | 内容 | bit/点 |
|---|---|---|
| raw64 | 恒等（int64 そのまま） | 192.000 |
| range | 差分なし + レンジ符号 | 41.037 |
| delta | 1 次差分 + レンジ符号 | 25.211 |
| 幾何v0 | 1 次差分 + 直前残差のビット数を文脈に | 24.524 |
| 幾何v1 | 直近 3 差分の中央値を予測子に | 23.921 |
| 幾何v2 | v1 + 復帰番号ごとに別の予測器状態 | 24.265 |
| **幾何v3** | **v1 + 軸をまたぐ文脈** | **22.032** |
| （参考）LASzip | | 22.219 |

**幾何v3 が LASzip を 0.8% 下回った。** 自前の符号器だけで、LASzip を一切使っていない。

効いたのは予測式ではなく**文脈の取り方**である。
Y を符号化するときに X の残差が何ビットだったかを文脈に使い、
Z には X と Y の平均を使う。走査線上では 3 軸の残差の大きさが連動するので、
軸ごとに独立な文脈では取り逃していた。

### 効かなかったもの

**幾何v2（復帰番号ごとに予測器状態を分ける）は逆効果**（23.921 → 24.265）。
1 発から複数の点が返るので格納順の隣は走査線上の隣とは限らない、という予想だったが、
分けると各系列の標本が減り、中央値予測が立ち上がらない分を取り返せない。
LASzip が同じ文脈を使っているので効くはずと考えたが、実測は否定した。
候補としては残してある（他のデータで効く可能性があり、費用は符号化時間だけ）。

## 列間の関係は「正規化の操作」ではなく「符号器の候補」にした

既存の正規化レイヤーは `residual_code`（他フィールドとの残差）を計画に書いていた。
PCC2 ではこれを符号器 `C_ATTR_XREF` に移した。参照先の列が先に復号されていれば
副情報は生じないので、幾何由来の順序と同じ理屈で成立する。

この移動には実務上の意味がある。**PCC2 は列ごとに独立して符号化するので、
周辺費用が加法的である。**

> **訂正（`scan_model_fitting.md` 27 節）。** 加法性は厳密ではない。容器の
> 自己記述の固定費があるため、**大きいファイルで漸近的に成り立つだけ**である。
> small_plane では列の和 12.177 に対し合計 12.497 で、差は +0.320 bpp。
 LASzip は列をまたぐ文脈を使うため、
`coding.tex` では (ii) 周辺費用の実測と (iii) 事後の貪欲な検証という
二段の仕掛けが必要だった（合わせて 3.1 bit/点）。自前の符号器ではこれが要らない。
各列について候補を並べて最短を採れば、それが全体の最適になる。

色についても「まとめて可逆色変換」と「隣の色を参照する鎖」の両方を書いて比べる。
AHN4 200万点では**鎖（7.404 bpp）が色変換（7.470 bpp 相当）より短かった**。
論文はこの比較をしていない。

## 端から端まで（AHN4 200万点）

基準は**同じ点を一度書き直した LAZ**（元の配布ファイル全体とは比べない）。

| 列 | 採択された符号器 | bit/点 |
|---|---|---|
| bit_fields | ctx | 0.651 |
| **X+Y+Z** | **幾何v3** | **22.032** |
| blue | sp(P=1) | 4.318 |
| green | 参照 blue + 空間予測 P=1 | 1.597 |
| red | 参照 green + 空間予測 P=1 | 1.489 |
| intensity | **sp(P=5)** | 8.676 |
| classification | sp(P=1) | 0.133 |

| scan_angle | ctx | 0.191 |
| point_source_id | delta | 0.001 |
| gps_time | delta | 2.263 |
| nir | sp(P=1) | 4.192 |
| Reflectance | 参照 intensity + 差分 | 1.327 |

```
基準 LASzip   17.8 MB   71.209 bpp
PCC2          12.7 MB   50.736 bpp    −28.8%
検証          全列一致 = true
5 軸          enc 55.2s / dec 1.8s / ピーク 1.10 GB / 決定性 バイト一致
```

**予測子の個数の 3 群分けが、符号器の中で自動的に再現された。**
レーザー由来（Reflectance）は P=5、画像由来（red/nir/blue）は P=1、
空間にも取得順にも構造のない Deviation は差分を取らない。
論文 4.4 節の条件 $\sigma^2(1-1/k) > \Lambda^2(\bar d_{(k)}^2 - d_{(1)}^2)$ が
予想する分かれ方と一致する。今回は閾値を一切書いておらず、実測だけで選ばれている。

## LAS/LAZ 非依存の確認

KITTI の生の `.bin`（float32 デカルト、無圧縮）を同じ器に通した。

```
121,194 点 / 出所 kitti / 幾何 f32bits / 列 4
  X+Y+Z        delta   49.649 bpp
  intensity    ctx     19.756 bpp
基準 元        1.9 MB  128.000 bpp
PCC2           1.1 MB   69.424 bpp   −45.8%
検証           全列一致 = true
```

LAS の点形式に縛られず、同じコンテナ・同じ符号器群で通る。
なお幾何 49.649 bpp は float32 のビットパターンをそのまま可逆符号化した値で、
極座標への復帰（既報 −85.2%）はまだ器に載せていない。

### 既存の構成との比較 — まだ 2.1% 負けている

| 構成 | サイズ | bit/点 | 元比 | 依存 |
|---|---|---|---|---|
| 元の LAZ | 439.6 MB | 71.349 | — | — |
| LASzip + 正規化レイヤー（既報。2026-09-23 に測り直して 295.0 MB / 47.881） | **295.2 MB** | **47.908** | −32.9% | LASzip |
| PCC2（自前符号器のみ） | 301.3 MB | 48.904 | −31.5% | **なし** |

**タイル全体では既存の構成のほうが 2.1% 小さい。**
200 万点では PCC2 が勝っていた（50.736 対 54.082）が、規模を上げると逆転する。
LASzip は点レコード全体を 1 つの文脈で符号化するので、
列を独立に扱う PCC2 が取り逃す相関が、点数が増えるほど効いてくる。

素直に読めば、**自前符号器は「LASzip から独立になった」段階であって、
まだ「LASzip を超えた」段階ではない。** 幾何が 22.542 bpp で全体の 46% を占めており、
ここを走査モデルで置き換えるのが次（`results/als_scan_structure.md`、見込み −27%）。

### 計算量とメモリ

enc 1409 秒・ピーク 26.60 GB は既存の構成（445 秒・22.8 GB）より重い。
候補を全点で符号化して比べているためで、`--sample-select N` で
選択だけ標本で行えば大幅に縮む（小ファイルでの選択のずれは 0.3%）。

## 他のファイル — 「決して悪化しない」保証は失われた

> **その後の経過（`scan_model_fitting.md` 19 節）。** 元の器を容器に包む退避路
> （A-3）を実装し、運用上の保証は回復した。最終出力が LASzip を上回るのは
> 10 ファイル中 3 件、最大 +0.317% に収まる。ただし**符号器自体は依然その 3 件で
> 負けており**（+1.1% / +4.9% / +8.2%）、退避路が出力で隠しているだけである。
> また退避路の復号には LASzip が要るので、「LAS/LAZ 非依存」はこの経路に限り
> 成立しない。


正規化レイヤーは LASzip を内側に持ち、恒等写像を族に含めることで
「元より悪化しない」を構成的に保証していた。**PCC2 は LASzip を置き換えるので、
この保証は成り立たない。** 実測すると勝ち負けが出る。

| ファイル | 点数 | LASzip | PCC2 | 差 |
|---|---|---|---|---|
| AHN4 31HZ1_20 | 200万 | 71.209 | **50.736** | **−28.8%** |
| plane (PDAL) | 28,185 | 16.689 | **12.826** | **−23.2%** |
| fullwave (YellowScan) | 10,750 | 73.480 | **60.922** | **−17.1%** |
| simple1_4 (Global Mapper) | 22,600 | 17.661 | **17.513** | **−0.8%** |
| autzen_trim (PDAL) | 110,000 | 43.507 | 44.028 | +1.2% |
| vegetation (RS Survey) | 10,683 | 49.845 | 54.576 | +9.5% |

負けている 2 件はいずれも**小さいファイルで gps_time の比率が高い**。
LASzip は GPS 時刻に専用の予測器（直近 4 つの時刻を保持し、
差が一定なら 1 記号で済ませる）を持っている。
2 次差分の候補（ctx2）を足して autzen は +5.2% → +1.2% まで詰めた。
vegetation は 10,683 点しかなく、適応モデルが立ち上がる前に終わる領域である。

**保証を取り戻す方法は 2 つある。**
一つは LASzip 出力をストリームの候補として持つこと（依存が戻る）。
もう一つはツールの層で両方書いて短い方を出し、どちらを使ったか申告すること。
符号器そのものの独立性を保ちながら運用上の保証を得るには後者が適う。

## 次

- **(A) ALS の軌跡復元** — 幾何 22.0 bpp の 78〜89% は「光線がどこに当たったか」。
  記録された走査角は 1 度刻み 35 段階で粗すぎるが、gps_time 順の点列から
  センサ位置を**推定**する経路は未検証。KITTI の −85% が成立した条件
  （疎な格子を成すこと）が ALS でも立つかどうか。
- **(B) 可逆な多重解像度** — 面・mipmap を予測子にして残差で可逆に戻す。
  Reflectance 8.8 bpp は P=5 の平均で底を打っており、粗いスケールの情報が
  効いている兆候がある。
