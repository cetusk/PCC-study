# コードの不具合を洗い出して直した記録（2026-09-23）

コード全体を 3 つの観点（I/O と器・符号器・並行性）で査読させ、出た指摘を全部直した。
直した後にもう一度独立に査読させ、そこで出た 5 件の確定の不具合と 12 件の危険も直した。

**可逆の符号化の結果はほとんど動かしていない。**15 件の中央 200 万点で、13 件は
bpp が 3 桁目まで同じ（2 百万点では 0.001 bpp が 250 byte にあたるので、「3 桁まで同じ」は
「差が 125 byte 未満」までしか言えない）。extra は +10 byte（138.659 → 138.734 bpp、
1065 点）、simple1_4 は約 +3 byte（12.095 → 12.096 bpp、22600 点、丸めを含めて 0〜5.6 byte）。
どちらも元のヘッダの点数の欄が中身と食い違っているファイルで、その欄を**元どおりに
戻すための費用**である。以前は戻していなかった。ログは `data/work/grid/size_v10.log`、
前は `bench_2m_final.log`。

**非可逆（`--eps`）の出力は変わった。**誤差を正しく数えるようにしたぶん、誤差上限
0.002 m の中央値が 17.954 → 18.017 bpp（`lossy.log` → `lossy_v10.log`）。
要約は **−14.3%（15/15）・四分位 [−32.2, −10.6]・幅 −36.5〜−8.5** のまま（修理の時点。
その後の改善ループで −14.7% になった。`results/losses.md` §27〜§30）。

検証は `python/verify_suite.py`（10 項目。isa は §7 で足した。最新は `suite_v21.out`）と `python/regress_fixes.py`（作り物で 1 件ずつ）。

## 1. 黙って結果を変えていたもの

| 不具合 | 症状 | 直し方 |
|---|---|---|
| 候補名を作る関数が静的な文字列を使い回していた | `--trace` のとき、並列の符号化で 101 件のデータ競合（TSan）と時々の double free（通常の符号化では候補名を糸の中で作らないので起きない） | 静的変数をやめて毎回組み立てる |
| 走査モデルの tan 表の遅延初期化 | 同上（初回に複数の糸が同時に表を作る） | 関数内の static で一度だけ作る |
| 字母の表を列の番地だけで使い回していた | 消えた標本の番地に別の列が作られると別の字母が当たる。`PCC_PRESELECT_ATTR=1` で 15 回中 5 回 segfault | 点数と値の指紋でも確かめる |
| 実験用の環境変数が復号にも効いた | 別の値で復号すると、誤りを出さずに別の点群が戻った | 復号中は常に既定値。pack は実験用の変数があれば断る |
| 列の復号結果を波の途中で `f.col` に書いていた | 同じ波の別の糸の探索と挿入が同時に走る（未定義動作） | 波ごとの局所に置き、合流してから移す |

## 2. 可逆のはずが戻らなかったもの

| 不具合 | 症状 | 直し方 |
|---|---|---|
| ヘッダの範囲・点数・GUID・ユーザーデータを書き戻していなかった | unpack --las のヘッダが元と違う | 読み込み時に数え直して**食い違う欄だけ**封筒に載せ、書き出し後に元の値を書き戻す |
| ExtraBytes の VLR に記述されていない余りのバイト | 0 で書き戻していた | 1 つの生バイト列の次元として運ぶ。印も封筒に載せる |
| ExtraBytes の名前が標準の列名（X など）とぶつかる | 幾何 X が ExtraBytes の X で置き換わった | 衝突する名前は `eb<番号>:<名前>` を列名にする |
| ヘッダ直後のユーザーデータ | LASzip の点データの位置の検査で書き出しが失敗 | その長さを点データの位置に足す |
| 1.4 の点形式 5 以下で旧形式と拡張の点数が食い違う元ファイル | LASzip が書き始めを拒む | LASzip には整合した値を渡し、閉じた後に元の値を書く |
| LAS 1.3 の内部の波形データ | 運んでいなかった | 1 本の EVLR として運び、位置の欄を書き直す |
| 空の ExtraBytes の VLR | 黙って消えた | 素の VLR として運ぶ |
| 負の値を持つ整数列を粗い格子で割る | 符号なしに読み替えて割っていたので商が 2^62 近くに飛んだ（戻りはした） | 絶対値の公約数・符号つきの商 |
| 非可逆（`--eps`）の粗い格子で古い刻みが封筒に残る | `.bin` に戻すと座標が約 206 m ずれた | 幾何の格子情報を外す |
| 非可逆の誤差を float32 に戻す前の値で測っていた | KITTI の 1 frame で戻した誤差が上限を 0.15% 超えた（上限に 2% の余裕を持たせて隠れていた） | 利用者が受け取る float32 の値で測り、余裕を無くす |

## 3. 壊れた入力・端の場合で落ちたもの

| 不具合 | 直し方 |
|---|---|
| 器の長さの検査が足し算で桁あふれ（`r.p + 長さ > 全長`） | 残りと比べる（`長さ > 全長 - r.p`）。走査の流れの内側も同じ |
| 壊れた本数・点数で巨大な配列を取って `bad_alloc` で落ちた | 流れの本数・負のゼロの個数・走査線の数は器に収まる上限と比べてから取る。**点数は比べようがない**ので、確保の失敗（例外）を捕まえて理由として返す |
| 計画の JSON の鍵が無いと際限なく操作を足した | 鍵が無ければ止める。`stoll` の例外もやめた |
| 計画の分母 0 で SIGFPE、残差の列の長さを確かめていない | 確かめてから計算する |
| 走査の標識で文脈の範囲外を引いた、幾何v4 の参照が先頭より前を指した | 0/1 と先頭までに縛る |
| KITTI の `.bin` の端数を黙って落とした | 16 byte の倍数でなければ断る |
| 格子に乗らない KITTI・100 点未満の KITTI が unpack できない | 封筒が空なら「格子なし」として書く |
| PLY の int32 を float のビットとして読んだ、short で未初期化のバイト、ascii の 32 列あふれ、長い行の分断 | 型ごとに読む。ascii は数を読む |
| 点 0 個の入力 | 断る（正規化が全列を落としていた） |
| 版 1 の器 | 読み方が変わったので版を 2 に上げ、1 ははっきり断る（その後の改善ループで模型が変わり、版 3 にした。いまは 3 だけを読む） |
| LAS 1.5 | 書き戻せないので読み込みで断る |
| `combine`（幾何を G-PCC に任せる構成）に定数の列がある入力 | 並べ替えの元の列を配列として直に読み、定数の列（値を 1 つだけ持つ）で範囲外を読んで落ちた（色だけの LAS で segfault）。値は `at()` で読み、解析用のコマンドは読み込み直後に全列を配列に展開する |

## 4. 失敗の扱い

| 不具合 | 直し方 |
|---|---|
| 検証に落ちた pack が壊れた器を本来の名前で残した | `<出力>.part` に書き、検証が通ってから名前を移す |
| 列の仕事の例外で、列の無い器が書かれた（`--no-verify` では残る） | 失敗した列があれば器を作らない |
| 例外で std::terminate、後始末が走らない | main で受ける。一時ファイルは後始末の型で必ず消す |
| `--eps` に数でない値・0 以下 | 断る（黙って可逆に落ちていた） |

## 5. 検証の穴

| 穴 | 直し方 |
|---|---|
| pack の自己検証は列しか比べない | **unpack --las と同じ道で書き戻し、元のファイルと器として比べる**。入れた直後に未記述バイトの印の欠落を捕まえた |
| `--sample-select` の経路は勝者に素通しの旗しか試さなかった | best_stream と同じ後追い（符号・光線・束ね・曲面、改善ループの後は速も）を関数にして両方から呼ぶ |
| `--force-geom` に旗つきの名前を渡すと「候補にならない」、記号版が勝つと別の名前で書かれた | 名前の末尾の旗を剥がして元の候補を探し、固定した候補には何も足さない |
| 検証の後半 4 項目（PLY・KITTI・force-geom・非可逆）がその場のコマンドだった | `python/verify_suite.py` にまとめた |

## 6. 未定義動作と機械による違い

| 危険 | 直し方 |
|---|---|
| 予測と残差の符号つき整数の桁あふれ（実数のビット列は 2^62 を超える） | `-fwrapv`（折り返しと定める） |
| 線形関係の検出で `a*d - nu*s` が 64 bit であふれる | 128 bit で計算。復元も同じ式 |
| 予測子の数え上げ `int k` が 2^31 点で負になり範囲外 | 64 bit |
| 掛け算と足し算を FMA にまとめるかが CPU と最適化で変わる | `-ffp-contract=off`。FMA による機械ごとの食い違いは無くなる（三角関数など libm の版の違いは別。可逆の経路は整数の表を使うので影響しない — と書いていたが、十進の格子の `pow(10, d)` が残っていた。§7 で直した） |

## 7. 構成を書き起こした査読で見つかったもの（2026-09-23）

`results/architecture.md` をコードから書き起こし、独立に査読させたところで見つかった。

| 不具合・穴 | 症状 | 直し方 |
|---|---|---|
| pack の「決定性」の検査が符号器を走らせ直していなかった | 選ばれた流れを器にもう一度**書き出して**比べるだけで、符号器の決定性は何も確かめていなかった。しかも食い違っても「不一致」と表示して器を確定していた（戻り値 0） | 選ばれた流れを、選択で温まった表（近傍表・走査の文脈・字母）を持たない新しい文脈で**符号化し直して**バイト列を比べる（`reencode_matches`、流れどうしは並列）。食い違えば戻り値 2 で何も残さない。試験用のつまみ `PCC_TEST_DET_FLIP` で 1 byte 反転させて捕まえることを `regress_fixes.py` 13 で確かめる |
| `字母` に記の対と生の版を作っていた | `字母` は `FreqModel` しか使わず記・生・束を読まないので、同じ長さのバイト列を余分に符号化していた（記号版が勝つと束・生束の後置検査まで呼び込んでいた） | 対も生の版も作らない。出力は 15/15 でバイト一致のまま、符号化は交互 3 回で 51.66 → 47.58 s（−7.9%、`ab_sym_v20.log`） |
| 十進の格子の復号で libm の `pow(10, d)` を呼んでいた | 可逆の経路なのに、libm の実装が違う機械では 10^d が 1 ulp ずれて、戻した float のビット列が変わりうる（§6 の「可逆の経路は libm に依らない」が成り立っていなかった） | 10^0〜10^22 の正確な定数の表（`exact_pow10`）。22 を超える指数は壊れた器として断る。KITTI 108 frame の .bin → PCC2 → .bin のバイト比較（verify_suite の kitti）と PLY 4 件の往復を通る |
| 非可逆の極座標の復号が libm の `cos`/`sin` を呼んでいた | 座標は空間予測の順序表と近傍表にも入る（`frame_world` → `attr.cpp` のモートン順）。libm の違う機械では 1 ulp のずれでセルが変わり、**可逆のはずの属性（KITTI の強度など）が戻らなくなりうる**。これまでの検証は 2〜20 mm だけで、極座標が選ばれる条件（KITTI は 0.05 m 以上、TLS の PLY は 1 mm から）を一度も通っていなかった | 四則演算と floor だけで組んだ sin/cos（`dettrig.hpp`、fdlibm の多項式。libm との差は最大 1 ulp）を、符号化側の誤差の見積り（`geom.cpp`・`main.cpp`）と復号（`frame.cpp`）の 1 つの関数 `polar_point` から通す。読み方が変わるので**器の版を 4 に上げ、版 3 の器は極座標だけ libm で戻す**。版 3 の器 40 件（KITTI 20 frame × 0.05/0.1 m、全部極座標）は新しい二値で旧と同じバイト列に戻る（`polar_v3compat_v20.log`）。作り物の版 3 の器を `cpp/tests/fixtures/polar_v3.pcc2` に置き、`regress_fixes.py` 14 で確かめる。verify_suite の lossy に 0.1 m（極座標）を、isa に KITTI 0.1 m と TLS の PLY 1 cm を足した |
| `-march=native` で建てていた | 建てた機械の命令セット（ここでは AVX-512）に依る二値で、別の機械で同じ値になるかは測っていなかった | 既定を `x86-64`（SSE2 だけ）に替えた（`PCC_MARCH` で選べる）。native で建てた二値と 80 件（15 件・KITTI 20 frame の可逆と 5 mm と 0.1 m の極座標・PLY 4 件・TLS の PLY の極座標）で器の md5 と相互の復号が一致（`isa_v21.log`。最初の 59 件は `isa_v20.log`）。符号化はむしろ −8.5%（`ab_native_x86_v20.log`）。verify_suite に isa を足した |

**査読で直したこと。**新しく足した表示の行が「決定性」を含んでいて、「決定性」を含む最後の行で
「バイト一致」を探す集計（`regress_pcc2.py`・`exp_order_matrix.py`・`exp_key_sweep.py`）が
全件を失敗と数えるようになっていた（見出しを「再符号化」に替えた）。試験用のつまみは
`--no-verify` と一緒だと壊れた器を確定させたので、検証のある経路でだけ効かせる。
再符号化の前に、選択で温まった表を捨てる（二重に抱えない）。糸の中の例外と、糸を立てられない
ときも異常終了しない。

**`字母` の変更は既定の経路でだけ出力が変わらない。**`--sample-select` と
`PCC_PRESELECT_ATTR=1` では、同じ長さの双子が控えや上位の枠を食っていたのが空くので、
選ばれる符号器が変わる。変更の前後の二値で 15 件の中央 200 万点を測ると
（`python/exp_sym_paths.py`、`sympaths_v21.log`）、`--sample-select 25000` は 2/15 件で
長さが変わり（USGS NY −0.03%、autzen-2023 −18 byte）、`PCC_PRESELECT_ATTR=1` は 7/15 件で
変わった。**autzen-2023 は −6.0%（15.63 → 14.69 MB）**で、双子に押し出されていた候補が戻り、
既定の経路とほぼ同じ大きさになった。ほかは USGS NY −0.10% と ±20 byte 以内。伸びる向きの
大きな変化は無い。`scan_model_fitting.md` の既定以外の経路の値（`exp_sample_*.py`・`exp_tradeoff.py`）は
当時の二値の記録として残す。

**費用（最終）。**変更前（v19 の二値、native）と最終（x86-64、版 4、査読の直しを含む）を交互 3 回で
比べると、符号化 50.43 → 47.43 s（−5.9%）、復号 8.22 → 8.13 s（−1.1%）、1 点あたりピークの中央値
673 → 680 byte（+1.0%。ファイルごとには上下し、最も増えたのは AHN5 の 1099 → 1254 MB）。
サイズは全件で同じ（`ab_v19_v21.log`）。

途中の値として、査読の直しの前に交互 3 回で比べると、符号化 52.87 → 50.67 s（−4.2%）、
復号 8.49 → 8.38 s（−1.3%）、1 点あたりピークの中央値 704 → 691 byte（`ab_v19_v20.log`。
どちらも既定の命令セットが native のときの値）。再符号化は `enc` の外で、15 件合計 4.30 s
（符号化の 8.2%）が pack 全体の時間に乗る。サイズは全件で変わらない。

**残したこと。**命令セットの比較は同じ機械の上で建て方を変えただけなので、glibc が実行時に
選ぶ版の違いまでは試していない（復号はもう libm を通らないので、効くのは符号化側の探索だけ）。
x86 以外（ARM など）では測っていない。既存のビルド用ディレクトリは `PCC_MARCH` を CMakeCache に
覚えるので、既定を変えても建て直すまで前の値のまま。

## 速さの費用

`-fwrapv`・`-ffp-contract=off` と、後追いの重複（模型を通らない符号器に旗を試す）を
外したことの差し引きで、15 件合計の実時間は**符号化 34.68 → 34.71 s（+0.1%）、
復号 7.35 → 7.46 s（+1.5%）**。前は `bench_2m_final.log`（2 回の最小）、後は
`size_v10.log`（1 回）で測り方が違う。同じ手順を続けて回した `size_v9.log` の符号化は
36.21 s なので、1 回ずつの揺れは ±4% ほどあり、この差はその中に入る。
pack の検証に「LAS に書き戻して照合」を足したぶん、pack 全体（検証込み）は長くなったが、
符号化の時間（`enc`）には入らない。

## 残した注意

- `LAS に書き戻して元と一致` は範囲と点数の欄を**全点を読んだときだけ**比べる
  （`--max-points` で切った入力には元のヘッダが当てはまらない）。
- 1.4 の波形データの位置は、EVLR を指していれば書き直したファイルでの位置になる。
  その欄だけは「元と同じ値」ではなく「同じものを指す」を保証する。
