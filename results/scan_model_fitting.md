# 走査モデル符号器 — 当てはめの誤りを見つけるまで

測定日 2026-09-19。`cpp/build/pccnorm pack` による実測で、
すべて往復検証（全列一致）と決定性（2 回書いてバイト一致）を通している。

## 一言で

**符号器を実装して測ったら規模で逆転した。原因を追ったら当てはめの符号が逆だった。**
ガウス・ニュートンの更新を引き算していたため、毎回逆方向に動いて固着していた。

## 1. 最初の測定 — 規模で逆転する

走査モデルを PCC2 の幾何の候補として実装し、規模を変えて測った。

| 規模 | 幾何v3 | 走査モデル | |
|---|---|---|---|
| 200 万点 | 22.032 | **20.801** | 走査の勝ち −5.6% |
| **4,929 万点（タイル全体）** | **22.542** | 24.964 | **走査の負け +10.7%** |

タイル全体では選択原理が自動的に幾何v3 を採ったので悪化はしていないが、
実装した符号器は採用されなかった。所要 enc 1086 秒・ピーク 26.6 GB。

**この節の数字はすべて、下記の誤りを含む実装で出したものである。**

## 2. 外れた仮説 2 つ

### 副情報が重くなる — 外れ

走査線ごとに 56 bit の副情報を送るので、規模が上がると重くなると考えた。逆だった。

| 点数 | 走査線あたり | 副情報 | 標識 | 残差 | 合計 |
|---|---|---|---|---|---|
| 50 万 | 160 点 | 0.866 | 0.317 | 19.046 | 20.230 |
| 200 万 | 258 点 | 0.556 | 0.309 | 19.936 | 20.801 |
| 800 万 | 490 点 | **0.307** | 0.311 | **22.898** | 23.515 |

規模が上がると走査線が長くなり、副情報は薄まる。伸びているのは残差だけ。

### 退避路が弱いから — 部分的に当たり、しかし主因ではない

モデルを採らない走査線は素朴な差分に退避する。そこが弱いと考えた。

```
200万点: 採用した線 14.88 bit / 退避した線 17.63 bit   モデルが良い
800万点: 採用した線 22.43 bit / 退避した線 19.02 bit   モデルが悪い
```

800 万点では、符号化器が「モデルが勝つ」と判断して採用した線のほうが悪い。
**判定そのものが壊れていた。**

## 3. 成分別に見ると面外が犯人だった

```
             面内     面外     z      計
採用した線   8.81    4.92    8.70   22.43
退避した線  10.01    1.56    7.45   19.02
差          −1.20   +3.36  +1.25   +3.41
```

面内はモデルが効いている（−1.20 bit）。面外が +3.36 bit 悪化して食い潰していた。

採用すると面外の予測が「直前点との差分」から「定数 off0（中央値）からの差」に
切り替わる。薄くない走査線では線の厚み全体に広がる。
**判定は面内しか見ていないので、この巻き添えが見えない。**

## 4. 試作と実装の食い違い

同じデータ・同じモデルなのに採用率が桁違いだった。

| | 掃引 | 走査線 | 分割 | モデル採用率 |
|---|---|---|---|---|
| Python 試作（300 万点） | 6,757 | 6,558 | 318（4.7%） | **0.998** |
| C++ 実装（200 万点） | 4,681 | 7,756 | **3,075（66%）** | **0.229** |

分割条件（走査角の幅が 20 度以上の掃引だけ分割を試す）を移植し忘れていた。
入れると分割は 6.8% に戻り、標識も 0.309 → 0.062 bpp に減った。
**しかし採用率は 0.224 とほとんど動かなかった。** 過剰分割は主因ではない。

## 5. 診断を 3 方向から一度に取る

走査線ごとに当てはめの様子を書き出す診断を入れた
（`PCC_SCAN_DUMP=<path>`。環境変数を付けたときだけ働き、符号化の結果には影響しない）。
解析は `python/exp_scan_diag.py`。

### (1) scipy と比べて桁違いに悪い

```
C++ − scipy の残差差: 中央 +15.14 bit/点  平均 +9.11  P90 +17.18
scipy のほうが良かった線: 91.5%
```

### (2) 反復すると悪化して固着する

```
反復    0      1      2      3    ...   11
      18.85  19.88  20.09  20.11 ...  20.11
```

1 回目が最良で、2 回目以降は悪化し、3 回目で完全に固着。
反復 0→11 の改善は 0.000 bit。**反復そのものが逆効果だった。**

### (3) 走査線の性質は主因ではない

不採用の線の 10% は高度が縮退していた（採用側は 0.2%）が、
点数の中央値は採用 292・不採用 307 とほぼ同じ。縮退は主因ではない。

## 6. 原因 — ガウス・ニュートンの符号

```cpp
g0 -= j0 * r;                             // g = -Jᵀr
double dth = (g0 * B11 - g1 * B01) / e;   // B δ = g を解く
double nt = th0 - dth;                    // ← 足すべきところを引いている
```

$B=J^{\top}J$、$g=-J^{\top}r$ として $B\delta=g$ を解いた $\delta$ は足すのが正しい。
引いていたので毎回逆方向に動き、境界 $|\theta_0|<\pi/4$ に張り付いて更新が
棄却され続けて固着していた。観測された 3 つの徴候すべてがこれで説明できる。

## 7. 修正後

| | 修正前 | 修正後 |
|---|---|---|
| 反復 0→11 の改善 | 0.000 bit | **+2.515 bit**（2 回で収束） |
| scipy との差 | +15.14 bit/点 | **+1.95 bit/点** |
| モデル採用率 | 0.224 | **0.296** |
| 幾何（200 万点） | 20.159 | **20.079** |
| PCC2 合計（200 万点） | 48.863 | **48.783 bpp** |

幾何v3 の 22.032 に対して **−8.9%**。

あわせて直したもの。

- 面外を採用・退避で切り替えず、常に中央値予測にした
- 退避路も中央値予測（幾何v1 と同じ）にした
- 採否の判定を残差の標準偏差からビット長に変えた。
  符号長を決めるのは裾の重さで、標準偏差では判断を誤る
- 判定の基準を、符号化器が実際に使う退避路と同一にした

## 8. 残っている課題

- **scipy との差 1.95 bit/点。** `shot` は最大 7 万、`Sz` は約 130 万（mm）と
  列のスケールが 6 桁違う。レーベンバーグ・マルカート法の対角スケーリングが要る
- **採用率 0.296 止まり。** 不採用の線は角速度の符号が採用側と逆（+17,182 対 −19,284）。
  走査の向きが逆のコースなのか、別の極小に落ちているのか未確認
- **800 万点とタイル全体が未測定。** 修正前の 22.797 / 24.964 は無効

## 教訓

このプロジェクトは「推定ではなく実測で選ぶ」を原則にしているが、
符号器の内側に代理指標が 2 つ残っていた。

1. 採否を残差の**標準偏差**で判定していた（符号長は裾の重さで決まる）
2. 判定の基準が、符号化器が実際に使う退避路と**違うもの**だった

どちらも「実測で選ぶ」から外れている。外側の選択原理だけ実測にしても、
内側に代理指標が残っていれば同じ誤りが起きる。

# 続き — LM の導入と、太い走査線の正体

## 9. レーベンバーグ・マルカート法で当てはめを作り直した

符号を直しても scipy との差が 1.95 bit/点 残っていた。
交互最適化では列のスケールの違いを扱えないためと見て、4 パラメタ同時の
LM に置き換えた。$A_{33}/A_{00}\sim10^{22}$ になるので、
$D=\mathrm{diag}(\sqrt{A_{kk}})$ で正規化してから解く。

目的関数は符号化器（`scan_predict`）と同じく $|\theta_i|\le45°$ で打ち切る。
当てはめの目的関数と符号化器の計算がずれると、実態に合わない最適化になる。

| | 符号修正のみ | LM |
|---|---|---|
| scipy との差 | +1.945 bit/点 | **+0.046 bit/点**（中央値） |
| scipy のほうが良かった線 | 92.6% | 68.1% |
| 反復 0→最終の改善 | +2.515 bit | **+5.769 bit** |
| モデル採用率（200 万点） | 0.296 | **0.656** |
| モデル採用率（800 万点） | 0.323 | **0.506** |
| 幾何（200 万点） | 20.079 | **19.128** |
| **幾何（800 万点）** | 22.694 | **22.122** |

**800 万点で初めて幾何v3（22.541）を下回った。**

## 10. 外れた推測 — 「角速度 0 の線で LM が止まっている」

8 節で不採用の線の角速度の符号が採用側と逆だと出たので、LM が動いていない線が
あると考えた。20 点以上の線に限って数えると、角速度が厳密に 0 の線は
2M・8M とも **0 本**だった。中央値 0 は、20 点未満の極小の線
（当てはめ以前に打ち切られ既定値 0 が入る）が支配していたもの。
LM が 1 歩も動かなかった線も 0.8〜1.1% しかない。

## 11. 外れた推測 — 「退避路が規模で弱くなる」

退避側の面内費用は、線ごとの中央値で 6.64（2M）→ 6.84（8M）とほぼ変わらない。
走査線の長さ別に見ても 6.4〜7.1 で平坦だった。

規模で悪化して見えたのは、点で重み付けすると 6.61 → 8.33 になるためで、
**少数の巨大な線が全体を引いている**。

## 12. 本当の原因 — 分割に失敗した太い走査線

走査線の長さ別の採用率（点で重み付け）:

| | 20-100 | 100-300 | 300-600 | 600-1200 | 1200- | 全体 |
|---|---|---|---|---|---|---|
| 200 万点 | 0.607 | 0.475 | 0.615 | 0.695 | 1.000 | 0.655 |
| 800 万点 | 0.657 | 0.615 | 0.428 | 0.712 | **0.351** | 0.506 |

1200 点超の帯だけが 1.000 → 0.351 と激減する。2M の範囲には無く 8M で現れる。

分割の結果を記録すると（8M、20 点以上の線）:

| 分割の結果 | 線 | 点の割合 | 薄さ中央 | 採用率 |
|---|---|---|---|---|
| 試みず（34 度未満） | 7,318 | 0.464 | 4.1 mm | 0.638 |
| EM が偏った | 3 | 0.000 | 11,075 mm | 0.000 |
| **判定で棄却** | **378** | **0.123** | **23,607 mm** | **0.000** |
| 分割した | 2,672 | 0.413 | 4.5 mm | 0.510 |

棄却された線は $w/r_0$ の中央値が **0.515**（閾値 0.5）で、わずかに外している。
しかし分割後も 12.4 m あり（成功例は 4.5 mm）、**2 群に分かれていない**。
閾値を緩めるのは誤った対処になる。

## 13. 太い線は走査線の集合ではなかった

失敗した線を EM で k 本に分けたときの薄さ:

| k=1 | k=2 | k=3 |
|---|---|---|
| 14.1 m | 7.15 m | 4.74 m |

**ほぼ $r_0/k$ で減る。** 一様に厚い帯を平行な短冊に切っているだけで、
構造を見つけていない。2 本の向きの差も 4〜5 度しかない。
分割に成功した線は k=2 で 0.0007〜0.0028 m（サブ mm）まで落ちる。

時間幅を測ると:

```
失敗した太い線: 2,092 点 / 時間幅 0.950 ms / 発射間隔 10 ulp / 時間の隙間 0 本
                地上の広がり 185 × 764 m
```

**単一の連続した掃引である。** 掃引の切り出しは正しく、複数の掃引が混ざっても
いない。0.95 ms の間に機体は 6 cm しか動かないので、厚さ 14〜17 m は
機体の移動では説明できない。走査幅 34 度をまるごと含むときだけ現れるので、
広い角度範囲では地上軌跡が曲がる、というのが最も素直な説明になる。
**ただしこれは説明であって、まだ測っていない。**

§9 で「走査幅いっぱいの掃引が平面でないのは 2 台のスキャナの混在が原因」と
書いたが、それは一部にしか当てはまっていなかった。混在した掃引は EM で
分離でき（229 本成功）、残る 298 本は線の集合ですらない。

## 14. 効かなかった対処 — 回転を実測で選ぶ

太い線では面内座標 $s$ が意味を成さないので、回転しないほうが安いはずと考えた。
モデルを採らない線について、主軸回転と恒等回転の退避路の費用を両方測り、
短い方を採るようにした。

| | 回転選択なし | あり |
|---|---|---|
| 200 万点 | 19.128 | 19.090 |
| 800 万点 | 22.122 | 22.102 |

**ほぼ効果なし（−0.02〜0.04 bpp）。** 回転は 1 次変換なので局所的な滑らかさを
壊さず、中央値予測の性能は座標系にほとんど依存しなかった。
太い線が高くつく理由は座標系ではなく、その領域の点そのものが予測しにくいこと。

面外は掃引を走査線に切り分けられたかの指標なので、改善の的は
当てはめではなく分割である、という解釈自体は機構として自然だが、
この標本では支持されていない。

### autzen-2023 — 採用率 0.037 で勝つ

採用した線 79 万点（16.79 bit）に対し、退避した線 2044 万点が 14.55 bit。
勝ちの中身はすべて退避路、すなわち掃引の分割・走査線ごとの主軸回転・
MedPred であって、`s = s0 + (Sz-z)tan(θ0 + ω·shot)` の当てはめではない。
座標変換そのものが幾何v3 の交差軸文脈より 4.9 bpp 良い。

### AHN5 — 分割が発火しない

53,296 掃引に対し分割は 1,079 回（2%）。1 掃引を 1 走査線として扱った結果、
面外 6.52 bit の帯になっている。AHN4 タイルで見た「太った掃引」と同じ症状。

### AHN3 — gps_time の表現が違う

2013 万点に対し掃引が 1639 万個、走査線あたり 1 点。時間差 > 200 ulp という
間隔条件がほぼ全点で成立している。AHN3 の gps_time は ctx2 で 9.693 bpp

採用率は 0.009〜0.035 と 0.477〜0.528 の二塊で、その間にデータ点が 1 つもない。

可能性を排除できていない。

変換だけのほうが短い。ただし低採用側の差は 0.025〜0.074 bpp（0.1〜0.3%）と小さい。

## 33. 先行技術（2026-09-20、独立査読の調査）

28〜30 節で扱った「順序を復元しながら費用は順序非依存」という性質について、
会話の文脈を持たない査読に先行技術を調べさせた。**構成要素はすべて既発表・既特許で、
新規性として主張できるのは 1 点だけだった。**

| 要素 | 状態 |
|---|---|
| 幾何の費用が入力順に不変 | **既知**（G-PCC のオクツリー、Draco の kd-tree） |
| データから走査順を内部で再導出 | **既知**（TMC13 の `--sortInputByAzimuth` / `--predGeomSort`、SerLiC ICML 2025） |
| 順序の情報を別チャネルで送る | **既知**（US10796457B2、shuffle coding） |
| 元の入力順を可逆に復元 | **既知（限定的）**（US10796457B2） |
| 上記を同時に満たす可逆符号器の実装と実測 | 公刊物は見つからず |
| 入力順がビットレートに与える影響の系統的測定 | **公刊物は見つからず（ここが空白）** |

### 危険な先行技術

1. **US10796457B2**（Van Beek, Intel, 優先日 2018-06-26,
   "Image-based compression of LIDAR sensor data with point re-ordering"）。
   明細書に「点位置を可逆符号化すればどの順で符号化しても X,Y,Z は同一」と
   順序不変性が明記され、「順序保存が必要な場合は符号化順の選択をデコーダへ送り
   元順序を再構成できる」とも書かれている。**最大の脅威。**
   差別化しうるのは「事前定義集合からの選択」対「任意置換の完全符号化」、
   および range image を前提にしていない点。独立クレームの内容は未確認。
2. **Kunze et al., ICLR 2024（shuffle coding）** と
   **Severo et al., IEEE JSAIT 2022（Random Order Coding）**。
   **「canonical ordering」という用語と log(n!) の理論枠組みを先取りしている。**
   向きは逆（彼らは順序を捨てて log n! を節約、こちらは順序を保って払う）だが、
   同じ道具立ての符号反転と見なされうる。
3. **G-PCC / TMC13** の `sortInputByAzimuth`、`predGeomSort`、
   `canonical_point_order_flag`。「順序不変な幾何符号化」は標準に既に入っている。
4. **LASzip**（Isenburg, PE&RS 2013）は再ソートしない。順序依存の代表例である。
   再ソートは外部ツール `lassort` の役割で、これは入力順を破壊する。
5. **Mongus & Žalik (IJRS 2011)** は LAS のファイル順をそのまま列として扱う。
   内部再ソートの記述は確認できず、先行技術にはならない。

### 帰結

- **「順序を復元しながら費用は順序非依存」を新規性の中心に置くことはできない。**
  しかも 29〜30 節の測定で、その性質は符号器ではなく鍵の一意性に依存すると分かった。
- **空白は「入力順のビットレート感度の系統的測定」だけである。**
  恒等 / Morton / 局所シャッフル / 完全ランダム / 逆順 を統制条件として
  比較した評価プロトコルの論文は見つからず、MPEG の共通試験条件にも
  順序の規定が無い。30 節がその測定にあたる。
- 既発表の `paper/coding.tex` の `sec:order-matters` が
  「幾何由来の順序を使うから色の費用は順序に依存しない」を既に主張しているので、
  本測定はその列を色から幾何に替えたものである。**新規性は
  「それが鍵の縮退の性質であり、完全に縮退したとき何が起きるかを定量化した」点に限られる。**

### 欠陥 1 — 「鍵だけを壊す」操作になっていない

**`gps_time` は鍵であると同時に走査モデル自身の説明変数である。**
`build_scan_ctx` は掃引の切れ目を「時刻差の中央値 × 20」で決め、
`enc_geom_scan` は `scan_predict` に `bg[i] - bg[0]` を渡す。量子化は両方を粗くする。

証拠が恒等条件の bpp に出ている。**AHN4 は最も細かい 10% 水準
（量子化幅 6.0e−7 秒）で既に 17.098 → 19.068 と +11.5% 悪化している。**
AHN4 の入力は降順隣接がほぼ 0 で鍵順そのものなので、恒等条件では
**復元される点順序が全水準で同一**である。つまりこの +11.5% は順序では
説明できず、**量子化による走査モデルの劣化そのもの**である。
**交絡（11.5%）は中間水準の主指標（±1%）の 10 倍ある。**

### 欠陥 2 — 逆順は雑音床ではない

AHN4 の逆順 Δ は **0 → +2.3 → +4.5 → +6.1 → +13.9 → 0** と、
タイ率とともに単調に増えて 100% で 0 に戻る。鍵にタイがあるとき、
逆順は `stable_sort` のタイを**決定的に逆向きに解く** —— 走査線内の点列を
反転させる、幾何的に意味のある処置である。100% で 0 に戻るのは、
鍵が完全に縮退すると符号化順 = 入力順になり、系列反転が差分符号にとって
ほぼ無償になるためである。**引くと調べたい効果が消える。**

30 節は自分で「符号つきの単一標本の雑音を信号から引く操作で、分散を減らさず
増やす。統計的な正当化は無い。この 1 数字で段階的な法則を支えてはいけない」
と書いていたのに、36 節はその指標を主表の唯一の列に昇格させていた。

### 欠陥 3 — 対照は原理的に動きえない

幾何v3 が 6 水準すべてで完全に一定（+56.1% / +150.5%）なのを
「測定系が健全であることの、事前に決めた証拠」と書いたが誤りである。
報告値は X+Y+Z のみで、量子化はスケール済み整数 XYZ に一切触らない。
**幾何v3 が動かないのは同語反復で、反証条件は発火しえない条件だった。**

### 欠陥 4 — x 軸が 5 桁空いている

平均群サイズで見ると 6 点のうち 5 点が **1.0〜4.0** に密集し、
最後の 1 点だけが **5×10³〜5×10⁵** にある。
タイ群は時間的に隣接する＝空間的に近い点の集合なので、置換の損害は
群の空間的な広がりにほぼ比例するはずで、群サイズ 4 で損害が小さいのは
設計の当然の帰結である。

### いま言えること

**符号器単独の性質ではない。** 入力順を恒等に固定したまま `gps_time` を
操作すると走査v1 の置換感度が変わるので、不変性は入力に依存する
条件つきの性質である。因果の向きは観測相関よりは強く支持される。

**それ以上は言えない。** 処置が単一でないので「鍵の単射性が原因」と
「時刻の精度が原因」を区別できない。「符号器ではなく鍵」は誤った二分法で、
正しくは **「走査モデルの順序不変性は、再構成鍵の単射性を前提とする
条件つきの性質である」**。

標本も実質 1 件である。vegetation は全水準で走査v1（29.485）が
幾何v3（25.592）より 15.2% 悪く、**そもそも走査モデルが採択されない**。

| 欠陥 | 扱い |
|---|---|
| 量子化が鍵と時間解像度を同時に壊す | **次の測定で閉じる** — ディザ条件（37 節） |
| 群サイズ 4〜5×10³ に観測点が無い | **次の測定で閉じる** — 交絡を切ってから log 群サイズ軸で刻む |
| 逆順を主指標にしていた | **いま直した** — 生 Δ を主とし、逆順は別条件として併記 |
| 標本が実質 1 件 | **直さないと決める** — この実験は機構の確認であって一般性の主張ではない |
| `plane` の飽和の機構 | **直さないと決める**（当面）— 29 節の観測でこの実験の対象外 |

「退避路に落ちる」という語を、容器の退避路（`--no-fallback` で切ったもの）と
走査モデル内部の退避（`sp.ok == false` のときの線内中央値予測）の両方に
使っていた。以後は後者を**線内の退避**と呼ぶ。

## 40. 取得順の置換を符号化したときの費用（2026-09-20）

多重集合符号器を系列可逆にするには、出力順から入力順への置換を送る必要が
ある。その上界は `log2(n!)/n` だが、取得順は空間的に相関しているので
実際はもっと安い。**上界で止めずに、実際に符号化して達成値を出した。**

`rec.ply` の並びから実出力順を取るようにした。復号は元々走らせているので
追加の計算は要らない。

| | 中央値 [bit/点] |
|---|---|
| 上界 `log2(n!)/n` | 18.489 |
| **実出力順（達成値）** | **7.800** |
| Morton 順（参考） | 10.197 |
| 一様乱数（達成値） | 22.874 |

**実出力順は上界の 45.9%（中央値）。** 基準順を取り違えていた分だけ
30% 高く見積もっていた。

**含意。** 恒等順で G-PCC（中央値 24.21 bpp）に置換を課すと 32.0 bpp 相当に

「$(0, 18.489]$ の範囲としか言えない」と書いていたが、**測って 7.800 に置き換える。**

8 条件のうち 3 条件で落ちたブロックが再開時に丸ごと飛ばされ、残りが
二度と生成されない状態だった。3 時間の測定が落ちたら黙って穴の開いた
データが出来上がる。条件数で判定するよう直した。

ほかに、置換の基準順が代理（Morton）だった件、ディザが「単射性」と
「取得順の情報」を同時に配っていた件、集計の nan マスクが片側しか
見ていなかった件、取得した LAZ が切り詰められてもヘッダは読めた件。

## 44. 作った縮退と自然に生じた縮退は違う（2026-09-21）

`python/exp_key_resolution.py`、出力は `data/work/key_resolution.txt`。

42 節の掃引（段階的）と 30 節の観察（閾値的）が食い違う理由を、
**発射間隔に対する量子化幅の比**で示す。発射間隔は同じ飛行線の中で
連続する点の時刻差の正の中央値。

| データ | 鍵重複 | 発射間隔 | 60% を作る量子化幅 | 比 |
|---|---|---|---|---|
| AHN4 _20 | 5.3%（自然） | 5.96e-07 s | 1.41e-06 s | **2.36** |
| vegetation | 0.0%（自然） | 9.08e-01 s | 3.59e-06 s | 0.00 |
| USGS NY | **57.7%（自然）** | 8.34e-06 s | — | — |

**AHN4 で 60% の縮退を作るには、発射間隔の 2.36 倍の量子化幅が要る。**
連続する発射が同じ時刻に潰れるので、走査モデルが当てはめに使う説明変数
そのものが失われる。中間水準で逆順Δ が 8〜16% と大きいのはこれである。

**vegetation は発射間隔が 0.908 秒**と桁違いに粗く、100% 以外の水準では
量子化幅が発射間隔に届かない（比 0.00）。だから逆順Δ が 5% 未満に収まる。

**USGS NY は発射間隔 8.34e-06 秒を保ったまま 57.7% が重複している。**
同じ発射の複数リターン（あるいは複数チャネル）どうしの重複であって、
発射どうしの重複ではない。

**帰結。** 掃引が支えるのは因果（原因は縮退であって分解能ではない。同じ
量子化幅のままディザで Δ が 0 に落ちるのがその証拠）であり、
**中間水準の効果量は、同時に壊した分解能の分だけ水増しされている。**
応答の形は掃引からは決められない。
